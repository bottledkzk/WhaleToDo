## 2. 小规模数据库

采用 PostgreSQL 16，沿用双方确认的技术栈。没有另建 SQLite 数据源。配置仅监听 `127.0.0.1:5432`，总连接20、共享缓存32MiB、work_mem 1MiB、关闭并行查询与JIT。应用连接上限6、AI角色上限3，AI实际池上限2；十个用户经连接池共享连接，不能把十个用户等同十个永久连接。

`users.demo_slot` 的唯一约束和1～10范围检查限制总账户最多10个；数据库函数在事务锁内分配空槽，Prisma可省略该字段。删除账户才会释放槽位；禁用账户仍占一个槽。此为课程演示容量策略。

| 领域 | 表与约束 |
| --- | --- |
| 账户 | users：用户名忽略大小写唯一、可空邮箱忽略大小写唯一、password_hash（禁止明文密码字段）、role/status、时间戳；邮箱验证发送/找回功能尚未实现 |
| 会话与去重 | auth_sessions：access/refresh摘要、family_id、失效/撤销；idempotency_receipts：作用域、键、请求指纹、响应和过期 |
| 内容 | tasks、plan_blocks、checkins、availability、user_settings；任务归属外键、locked、起止/工时约束、版本和删除标记 |
| 同步基础 | sync_batches、sync_mutations、sync_changes；批次与逐项回执分离、独立序列；尚无同步路由 |
| 积分 | daily_claims、point_wallets、point_ledger；签到唯一性、可用/预占非负、每事件幂等；签到API待Weiding |
| 权益与 AI | entitlements、ai_requests；VIP权限仍待产品确定，AI请求保存状态、摘要指纹、用量与有限响应，不保存输入正文 |

邮箱、角色、默认设置有字段和约束，不表示这些字段已经接入APP。订单/商品表等待Weiding的字段建议再作迁移，不先替其冻结业务。

迁移位于 `server/prisma/migrations`，由 Prisma 6.19.3 部署。Prisma映射由实际数据库读取，CHECK、RLS、表达式/部分索引和函数以 SQL 迁移为准；不要用 `db push` 或删除迁移目录覆盖这些约束。当前4个完成迁移；策略首次引号失败已标记回滚并修复，失败/恢复证据留在个人测试区，未改已有业务数据。

## 3. 权限与事务接入

- `whaletodo_migrator`：统一schema/迁移角色，由Bottledkzk管理，不交给客户端或常驻应用；不具有superuser/CREATEDB/CREATEROLE。
- `whaletodo_app`：必要DML，不能DDL或直接修改用户role/status；不读取迁移表。客户端永远不获取数据库连接串。认证API必须拒绝请求体自选role/VIP。
- `whaletodo_ai`：只读会话验证所需列；不能读密码/refresh摘要；可进行钱包、流水及AI请求的必要事务。
- 事项、计划、打卡、空闲、设置、同步批次/明细/变更启用RLS。每次请求必须在数据库事务内以认证取得的user_id调用 `SELECT set_config('app.user_id', $1, true)`，再执行查询；不能相信客户端传user_id，不能在池连接上用永久SET。无身份时看不到内容，事务结束自动清除上下文。
- 账户/会话查询属于服务端特权能力，不套用需要预先知道user_id的内容RLS；Weiding需在其路由和仓储中做完整账户归属授权。

连接参数通过受限私密渠道配置；仓库只放模板。远程访问数据库用受限SSH隧道，不开公网5432，也不向团队转发root主密钥。队友本地可复用CI初始化脚本，但其中假密码只用于临时容器，不能用于实际服务器。

## 4. AI API

公开基址 `https://api.whaletodo.top:8443/api/v1`。只有 `/ai/*` 转到独立回环8081服务；账户路径仍503，不能把AI健康200当账户登录已部署。

| 路径 | 行为 |
| --- | --- |
| GET /ai/health | 无敏感细节健康检查 |
| GET /ai/models | 需Bearer访问令牌，返回服务端model_code允许列表 |
| POST /ai/requests | 需登录和积分；正文见下；返回请求状态与文本 |
| GET /ai/requests/{client_request_id} | 只查本人请求；未知/越权统一拒绝 |

```json
{
  "client_request_id": "00000000-0000-4000-a000-000000000001",
  "model_code": "deepseek-default",
  "mode": "chat",
  "prompt": "请帮我整理今天的安排",
  "context": "用户主动选择的简短安排摘要，可省略"
}
```

mode 为 chat/plan/review/diary/share_copy。当前返回文字建议/草稿；不直接修改事项，不执行模型工具，不声称已完成Agent自动排程。多轮历史由后续客户端/会话层提供明确选择摘要，不能默认上传数据库或私人备注。

服务端固定 DeepSeek 官方HTTPS、固定模型映射，显式关闭思考，最大输出2048、超时45秒、不跟随重定向、不自动重试；请求最大32KiB，prompt最多4000字符、摘要2000。客户端不能指定供应商URL、API Key、max_tokens或账户权限。凭据经systemd LoadCredential从服务器0600文件加载；无Key配置接口、无客户端Key、无请求正文/令牌日志。

请求在事务中完成限额检查、积分预占与唯一回执，然后释放数据库连接再调用模型。默认演示策略是每次预占1积分，每用户每天5次、全局40次，每用户30000/global120000 Token；并发最多2，用户每分钟3次；这些是可调整安全阀，不是VIP正式权益。免费用户没有自动赠送积分，需等待Weiding的签到接入。

同用户同client_request_id同体只返回原结果，不再次调用/扣分；异体409。成功结算一次。供应商明确拒绝会释放一次；超时、服务异常、空正文/截断、状态不明或进程重启留下unknown，保留积分与保守预算，返回202可查，**不猜测成功、不自动重发**。unknown目前需运维核对上游后处理，不对用户开放任意退款/改余额入口。供应商费用与应用积分并非同一口径。

## 7. 2026-10-24 交叉评审后的接入确认

本节确认仓储契约，不代表Weiding的适配代码已提交或实测。

- 用户名与可选邮箱都使用现有lower表达式唯一索引；查询用参数化 `lower(column)=lower($1)`，不使用ILIKE。输入先trim，邮箱空串转null；判重查询不能替代唯一约束，命名唯一索引冲突须映射409，避免并发时500。
- `point_ledger.balance_after`就是可用积分快照，对应`point_wallets.available`；已有reserved_after与双delta，不增同义列。family_id为NOT NULL，access/refresh_hash各自UNIQUE，family_id有索引。
- 已登录业务的幂等scope由服务端认证身份生成，固定为 `v1:<operation>:<user_uuid>`，operation为claim/order/sync等内部白名单。客户端不能传scope或决定user_id。
- 未登录注册的scope为 `register:v1:<HMAC-SHA256(scope_key, normalized_username)>`；normalized_username采用已校验ASCII用户名trim+小写。不使用IP散列作为身份范围，共享校园网/NAT会误碰撞，换网也会破坏重试。
- scope归属之外仍须比较完整白名单请求的HMAC指纹（含password、display_name、email等实际支持字段）；同scope/key异体409，只有同体才可返回原注册结果。缓存只存指纹与最小注册结果，不存原密码、令牌或完整请求。scope/fingerprint的密钥须服务端持久配置并作用途隔离，不能继续用仅进程内随机密钥支持持久化回执。
- 回执首轮TTL为24小时，过期判定与同键重新占用必须在事务内完成。expires_at索引暂缓，10用户规模不阻断合并；后续清理频率/表增长需要时由本侧新增迁移，不修改已应用迁移。
- 容量满按PG SQLSTATE 23514且诊断标记DEMO_USER_LIMIT映射409/演示容量已满；不能把所有23514都当容量问题，其他字段CHECK仍按字段校验处理。
- sync_mutations已有owner_batch_scope RLS，读写必须与batch在同一认证事务中set_config；应用仍显式验证batch归属。刷新采用同事务条件撤销旧会话并检查唯一成功者，再插入同family新会话；并发刷新失败分支的重放/整链撤销也需用真实数据库集成测试验证。
- 迁移目录继续沿用现有时间戳目录。订单/支付字段待Weiding建议另作迁移；本轮不新增真实付款或删除账户API。订单/账本保留和环境隔离在引入该业务前共同冻结。
