# 小米 14 Pro 实际验证准备

本次从已合并主分支增加本机设备／权限状态入口，不宣称已完成小米真机验收。目前只发现 Android 16/API36 模拟器，小米未连接；手机当前 Android、HyperOS 版本和安装版本待实际读取，不能按型号推断。

**HyperOS／锁屏到点／相机／分享／账户 AI 均未在小米真机验证；API36 模拟器结果不能替代。API26／31／33 只检查设置路由策略分支，未运行这些版本的系统镜像；CI 只编译 AndroidTest，不冒称已在 CI 运行设备测试。**

按交叉评审补齐通知、提醒精度、电池优化、相机四类可点击入口：API31+ 精度设置带本应用 package URI，低版本回退应用信息；电池仅打开优化列表，相机打开应用信息。每类入口缺失或权限拒绝均可安全回退；不新增精确闹钟或电池豁免权限，不自动修改策略。本版未声明精确闹钟权限，不能靠新增入口宣称已支持精确提醒。CI 增加 `:app:assembleVerificationAndroidTest` 以独立验证测试代码可编译。

## 本次交付

“我的 → 设置 → 设备与兼容性”显示公开 Build 字段中的厂商、型号、Android/API、当前应用版本，以及通知权限、精确提醒能力、电池优化豁免和相机权限。返回系统设置时重新读取状态。小米／Redmi／POCO 仅影响辅助说明，功能判断始终以 API 和实际权限为准；不反射隐藏 API，不读取序列号、IMEI、Android ID、账户或用户记录，不上传／持久化诊断信息。没有统一公开接口保证准确识别 HyperOS 名称／版本，不把 Android 版本当成 HyperOS 版本。

系统设置入口使用 Android 标准通知、API31+精确提醒、电池优化列表及相机对应应用信息 Intent，厂商未提供入口或拒绝打开时回退到应用信息，再显示手动查找提示。入口由用户点击，不自动开启权限、忽略电池优化或尝试未公开的小米组件。未允许精确提醒时明确显示普通提醒可能延迟；通知总开关允许也不代表各通知类别、勿扰和锁屏一定放行。

## 连接手机后执行

1. 用户在手机端授权 USB 调试；先记录型号、实际系统版本、字体/显示大小、导航方式、安装包版本与签名。禁止清空、卸载旧体验包或预览包来解决签名冲突。需要测试包时只安装 `io.whaletodo.app.verification`，已有公开预览升级另走同签名与数据保留验证。
2. 打开设备与兼容性页，对照手机设置；拒绝／允许通知后返回，确认状态立即更新。默认电池策略、用户当前自启动／锁屏设置分别记录；不自动改安全和电池设置，不承诺精确后台到达。
3. 本侧界面／core：默认和大字体、暗色、手势底栏／键盘遮挡、预览日历、跨日时区、冷启动／覆盖升级后数据保留。先用合成记录，发现问题按具体布局或规则修复。
4. 队友系统模块：通知类别关闭／拒绝、前台／后台／锁屏到点、改期取消／重启重建；系统 Picker 选图和取消、相机授权／拒绝和旋转返回、相册保存、真实目标 App 接收图片 URI。逐项给实际步骤与脱敏结果，模拟器不能替代此表。
5. 双方网络／AI：合法账户、服务器已就绪后验证登录／换号、断网和切后台、日记／分享配文，以及原 ID 未决恢复。真实模型和邮件分别记录，禁止用 fixture 或生产演示绕过验证。
