# Agent 日期安排与主动账户同步

本轮按项目发起人 2026-10-30 明确要求实现客户端、服务端与新增迁移；本 PR 不等于生产发布或公开 APK 更新

## 用户流程

- 登录仅切换账号本地分区，不触发日程 GET/POST，不搬迁访客记录
- 设置 → 账户同步 → 云端备份 → 数量预览 → 确认，才上传当前账号日程并替换上一份备份
- 设置 → 账户同步 → 覆盖同步／兼容同步 → 预览 → 确认，才应用云端日程；拉取不会自动再次上传
- 覆盖仅替换当前账号的事项、安排、打卡、按日工作时间、旧版工作时段设置和提醒，不清其他账号、访客、日记、资料或 Agent 历史
- 兼容保留本地同编号记录，加入云端独有事项；冲突云端安排不导入，其事项可重新安排
- 日程上传和下载均需服务端有效 VIP，既有 `/sync/push` 与 `/sync/pull` 同样增加 VIP 门禁
- 日记、昵称和 motto 不受 VIP 限制，登录及前台运行时自动随账号；离线修改保留，15 秒轮询或显式重试恢复
- 同字段在两端相对上次确认副本均发生修改时，不静默覆盖；在账户同步页选择保留本地修改或使用云端资料
- Agent 会话仅在本机按账号保存，云端文档白名单排除会话、消息和凭据。既有 AI 单次结果回执仍支持原 ID 查询，不提供云端历史会话接口

## 日期安排与采纳

使用“调整日程”，打开日程读取和本次编辑授权，必要时点击“刷新权限”；UI 显示编辑能力是否就绪，模型仍由内部可信路由决定

- 一个已安排、未固定、未开始、未完成的事项：支持明确年月日、今天／明天／后天、本周／下周星期、24 小时或上午下午点数，代码按日程时区编译时间
- 一个未完成、完全没有安排且有预计工时的事项：新增 `schedule_task` 提案，时长严格等于预计工时；采纳后生成稳定安排编号
- 新客户端发送 `action_version=2` 和结构化事项、安排、日期、时区、实际可用时段；旧客户端不会收到其不能采纳的新增安排操作
- 意见通过机器字段绑定尚未采纳的目标，重新生成提案，不应用旧提案
- 同名、多目标、不支持的日期表达、DST 缺失或重复时刻、部分日程副本均需澄清，不猜目标
- 服务端和本地均检查工时、未来时段、截止、可用时间和重叠，本地窗口为 14 天；大批量安排仍用现有排程预览入口，本轮日期编译限一个明确目标
- 预览不写库；人工采纳使用准确快照和事务回执，重复采纳及过期快照不能写入
- 预览展示完整年月日和移动前后时段；坏变更不能被丢弃后部分采纳其余变更
- 配文在品牌替换后再次校验三条短句，避免退化成一条身份说明仍计费

## HTTP 与数据库

前缀 `/api/v1`，与账户／Agent 共用 ApiClient、TokenStore 和会话代次

| 接口 | 规则 |
| --- | --- |
| GET `/account/cloud/schedule` | 登录＋VIP；无备份为 revision=0、payload={} |
| POST `/account/cloud/schedule` | 登录＋VIP；用户确认后调用，按 revision 比较替换完整备份 |
| GET `/account/cloud/profile` | 登录；独立资料文档 |
| POST `/account/cloud/profile` | 登录；按 revision 比较更新合并后的资料 |

响应 `data={revision,payload,updated_at}`，updated_at 为毫秒或 null。写请求 `{revision:<已读版本>,payload:<白名单内容>}`，不接收 user_id、VIP、余额或其他字段。版本 0 仅创建首份；旧版本且内容不同返回 409；内容完全相同的响应丢失重放返回已有版本，不重复提交

日程 payload：schema_version=1、tasks、blocks、checkins、work_times、settings、reminders。只输出支持的领域字段，不输出本地 owner／server_version 或其他表。资料为 entries，仅 profile.nickname、profile.motto、diary:YYYY-MM-DD。新设备本地空内容不会删除云端记录；删除依据上次确认副本与本地差异

资料同步三方比较上次确认、本地及云端；按版本提交后，在 Room 事务里只应用请求期间没有修改的字段。较新本地编辑保留供下轮上传，确认副本保存在当前账号偏好，重启后仍能恢复离线差异

日程应用前重读云端版本，并在 Room 事务内重查本地内容、账号、VIP 与旧同步未决状态；失败不部分写入，最终提交后重建提醒。设备时区、外观、本机图片 URI 不上传

第八迁移 `202610300001_account_cloud` 新建 account_documents，主键 user_id＋kind，合计 23 张业务表。JSON 类型、大小、kind 和版本均有约束，按账号 RLS；仅授权 whaletodo_app，AI 角色不能读写。SQL 全部参数化，旧迁移未改。发行包边界推进至八迁移；gateway profile 仍禁止启动账户 API
