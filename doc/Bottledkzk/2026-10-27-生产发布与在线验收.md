# 生产发布与在线验收

本轮交付可执行发布包、账户进程配置、限量线上验收工具和0.5.3-preview.1候选构建。源码包含已合并的账户/AI桥接及查询429恢复。**PR评审通过后发布冻结提交**；本文件、包和CI均不代表生产已经切换。

前置只读检查确认当前账户API仍为未部署占位，生产第五/第六条迁移尚未应用，旧AI服务仍在运行；详细主机/数据库状态留在本机私有证据，不写入仓库。真实邮件投递仍缺失，当前生产没有可直接用于APP邮箱登录的验收账户。不能创建生产DEMO种子、绕过邮箱验证或伪造签到积分来凑闭环。

## 1. 冻结与包

在干净的已提交目录运行：

```text
python script/prepare-ai-release.py --profile full --output <全新私有目录>/production.tar.gz
```

`full`包含账户API、AI源码/工具、锁定依赖清单、六条原始迁移、账户服务和反代snippet。`gateway`只含前五条迁移，manifest明确`account_api_start_permitted=false`，不能用它发布账户服务。依赖、真实.env、凭据、签名库、数据库备份不进入包。

manifest记录提交、文件SHA256、迁移边界、提示策略和Node24.15.0；解包后逐项复核，不只核对归档名。gzip/tar元数据固定，同一提交/同profile的打包字节可重复；不对APK作逐字节可重现承诺。目标目录不可覆盖已发布版本。

## 2. 生产执行顺序

1. 只读刷新活动发布、服务PID/内存、数据库迁移校验历史、在途AI与预占、备份/恢复timer。旧443服务、DNS和其他进程不动。主机资源有限，准备依赖不与在途模型调用或集成测试并发。
2. 验证包及候选目录；从相同package-lock准备依赖，执行`npm ci --ignore-scripts`、`npx prisma generate`、类型检查与真实模块导入。不得用CI的内存账户仓储上线。
3. 在服务器生成新备份，恢复到**新临时库**；以受限迁移角色演练四→六条迁移，核对旧表/旧列行哈希、权限、钱包及unknown预占保持。正式dump不复制到本机，不启用清理timer。
4. 确认无其他迁移或活动发布，重新备份；使用`db:plan`/`db:apply`及最新备份门禁只追加两条原始迁移。执行已审`grants.sql`和AI entitlements只读授权，复核六条迁移校验、受限角色、数据保持。schema生成不能代替实际迁移。
5. 账户API使用独立系统用户`whaletodo-api`，源目录由管理员拥有、服务用户不可写；`/opt/whaletodo/api-current`与旧AI的`/opt/whaletodo/current`分别保留回退目标。先本地启动/验证账户，再在活动AI请求为零时升级网关，避免混用不兼容版本。
6. 通过`LoadCredential`提供`database.url`及持久`idempotency.secret`，不作为命令行、普通.env或Git变量。账户URL必须为`whaletodo_app@127.0.0.1:5432/whaletodo?schema=whaletodo&connection_limit=2`且带私有密码。HMAC密钥至少32字符，后续发布保持原值。先在相同服务身份/credentials设置下运行`node src/ops/api-main.ts --check`；它不连库，不能代替步骤4。
7. `whaletodo-api.service`固定回环8080、禁用支付、禁止DEMO配置和源码目录.env、限制内存/任务。AI继续回环8081和既有限额。核对总连接/资源预算，不能仅因MemoryMax可设置就宣称主机容量足够。
8. 本地检查账户health、匿名me/AI models为401，已有合法账户能读资料/钱包；网关提示策略和源文件哈希匹配。真实注册仍需Weiding接通邮件投递后验收，`sent:true`不能当送达证据。
9. **只在现有8443 TLS API虚拟主机**增加`location /api/v1/ { include /etc/nginx/snippets/whaletodo-api-proxy.conf; }`；保留更优先的`/api/v1/ai/`到8081，HTTP80继续不代理账户令牌，其他路径维持原占位。先`nginx -t`再reload，不改443。账户health从公网503变200后才进入真实验收。

启动失败回退对应源码软链接/服务和反代配置；保留已应用的追加迁移。已有新数据后不能自动恢复旧dump或删除新表；恢复数据库必须另有明确恢复范围和回执。备份/恢复timer沿用，maintenance继续未启用。

## 3. 最多两次合成真实调用

验收工具使用已有合法账户的短期访问令牌私有文件；不生成账户、不发验证码、不领签到、不调价/赠分。必须先在APP完成真实登录/签到，并记录余额来源；首日1积分可能不足AI保守预占，工具会拒绝余额不足而不会替用户改账。

在冻结服务器代码目录执行，只读预检（**零模型POST**）：

```text
node tools/online-acceptance.ts --base-url https://api.whaletodo.top:8443/api/v1 --token-file <私有令牌文件> --source-commit <冻结40位SHA>
```

预检核对账户/AI health、匿名401、账户归属、提示策略版本、钱包和两次预占预算。`--source-commit`是操作者声明，不是HTTP自动证明；必须与步骤1–8的部署manifest/源哈希回执共同使用。`--max-output`必须与部署限额一致，默认2048。

通过后运行一次：

```text
node tools/online-acceptance.ts --base-url https://api.whaletodo.top:8443/api/v1 --token-file <私有令牌文件> --source-commit <冻结40位SHA> --receipt <全新私有回执.json> --execute
```

仅发送两种固定合成输入：diary和share_copy。每次POST前先持久化原UUID/输入指纹/已尝试状态，成功核对结构、实际tokens、扣分与钱包变化；没有原始正文、邮箱或令牌写入回执/终端。拒绝、结构失败、unknown、IO或查询429/5xx都会停止，不循环消费模型。

遇未知时保留同一文件，稍后用**相同账户/源码/限额**运行`--resume`代替`--execute`。已尝试项只GET原ID，绝不重POST；前项确认成功后才允许尚未尝试的第二项，总POST尝试数仍最多2。已失败的验收不能用resume继续花费。进程崩溃留下`.lock`时，先确认原进程已结束再由操作者删除锁，不能凭超时自动抢锁或换新回执重试。

`passed`只表示此次HTTP结构/计费核对，不是APP闭环或内容质量通过。还必须单独记录：真实账户注册/邮件送达、APP登录与签到、日记草稿预览/确认保存、文字配文编辑、提案预览/采纳、断线/失效/换号隔离，以及双方真机。总调用预算先冻结；不要为每个失败场景重复消费真实模型，故障注入仍在隔离环境做。图片分享页AI配文和同步不在本PR，继续各自交付。
