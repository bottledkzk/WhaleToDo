# 演示运行手册（2026-10-28 更新）

适用：答辩现场、组内联调、给评审演示当前 main。
基线：**main `63a6ff6`**（#26/#29 已合并）；#31/#32/#33/#34 待评审；#30 已合并。
本手册只描述本地演示，不代表生产已部署/已验收。

## 1. 前置检查

- Node.js 24（服务端 `node src/main.ts` 直接运行 TypeScript）
- JDK 21：`<JDK21>`
- Android SDK / `adb` 可用；仓库根目录记为 `<repo>`
- 默认使用 **verification 测试包** `io.whaletodo.app.verification`

### 1.1 选择设备（必须）

```powershell
adb devices
$env:ANDROID_SERIAL = '<目标设备序列号>'
adb -s $env:ANDROID_SERIAL get-state
```

多设备时所有 `adb` 命令都带 `-s $env:ANDROID_SERIAL`，不要依赖“默认设备”。

### 1.2 首次准备

```powershell
cd <repo>/server
npm ci --ignore-scripts --no-audit --no-fund
npx prisma generate --schema prisma/schema.prisma
```

内存模式仍建议执行 `prisma generate`，因为 `src/main.ts` 会导入 Prisma 仓储。

## 2. 服务端：demo 内存模式（T28 seed）

不配置 `DATABASE_URL`；重启后账户、签到、订单等内存数据清空，demo 账号和 3 个商品会重新 seed。

```powershell
cd <repo>/server
$env:NODE_ENV = 'demo'
$env:DEMO_EMAIL = 'demo@example.invalid'
$env:DEMO_PASSWORD = '<至少8位，现场设置，不要提交>'
$env:DEMO_DISPLAY_NAME = '演示鲸鱼'
$env:PAYMENT_PROVIDER = 'mock'
$env:MOCK_WEBHOOK_TOKEN = 'local-test-token'
$env:PORT = '8080'
$env:HOST = '0.0.0.0'       # 手机通过局域网访问时必须；只在本机可改回 127.0.0.1
$env:DATABASE_URL = ''      # 空 = 内存仓储
node src/main.ts
```

- `NODE_ENV=demo` 才允许 `PAYMENT_PROVIDER=mock`。
- demo 启动会 seed 演示账户和 3 个商品：`vip_7d`、`vip_30d`、`points_100`。
- 商品只在 **demo + 无 DATABASE_URL** 时 seed；其他环境/真库不 seed。
- `DEMO_*` 与 `DATABASE_URL` 同时存在会 fail-fast；演示前确认 `DATABASE_URL` 为空。
- 重启内存服务会重新 seed；已产生的账户/签到/订单数据不会保留。
- 服务端日志会打印 `storage: memory(dev only)`、`demo_seed`、`demo_products`，可据此确认。

## 3. T44 开发收码（仅 demo + 内存，不接 SMTP）

用途：没有 SMTP 时，在演示现场完成邮箱注册/找回的验证码流程。
**只在 demo 内存模式使用，不要在生产/真库开启。**

```powershell
# 启动服务端前设置；如果服务已启动，设置后重启
$env:DEMO_EMAIL_OUTBOX = '<已有父目录>\outbox.jsonl'
node src/main.ts
```

- 仅 `NODE_ENV=demo` 且无 `DATABASE_URL`；production/development/test 或配置了 DB 时出现该变量，启动会拒绝。
- 每行 JSON：`{"time","purpose","email","code"}`；文件权限目标为 `0600`。
- Windows 的 `stat.mode` 不能可靠表达 ACL，权限断言在 POSIX/CI 执行；Windows 本机演示不要把该文件放在共享/可读目录。
- 父目录必须预先存在；已存在文件在 POSIX 下若 group/other 可读写会启动拒绝（不静默改权限）。
- 写入失败会让 send-code 返回 500，不会返回 `sent:true`。
- 日志只记 `demo_email_outbox:true/false`，不记路径/验证码；响应和数据库也不落明文码。

### 3.1 现场读码步骤

```powershell
$base = 'http://127.0.0.1:8080/api/v1'
$body = @{ email = 'demo-register@example.invalid'; purpose = 'register' } | ConvertTo-Json -Compress
curl.exe -s -X POST -H 'Content-Type: application/json' --data $body "$base/auth/email/send-code"

# 读最后一行；不要把 code 打印/贴到群里/写进报告
$entry = Get-Content -LiteralPath $env:DEMO_EMAIL_OUTBOX | Select-Object -Last 1 | ConvertFrom-Json
$code = $entry.code

$body = @{ email = 'demo-register@example.invalid'; purpose = 'register'; code = $code } | ConvertTo-Json -Compress
$ticket = (curl.exe -s -X POST -H 'Content-Type: application/json' --data $body "$base/auth/email/verify" | ConvertFrom-Json).data.ticket
```

- `send-code` 返回 `202` 后立即读文件；`verify` 用 `$code` 换 ticket（60 秒、单次、绑定 purpose/email）。
- 注册/找回请用未注册邮箱（示例 `demo-register@example.invalid`）；不要用 T28 seed 的 `demo@example.invalid`，否则会邮箱已存在。
- 内存模式重启后文件仍保留，但内存里的验证码摘要已清空，旧 code 不能继续 verify；重新 send-code 取新码。
- **不要提交 `outbox.jsonl`、不要贴 code、不要把路径写进公开文档/日志**；演示结束删除该文件。

## 4. 构建并安装 App（verification 包）

默认只用测试包 `io.whaletodo.app.verification`，不覆盖正式包与预览包。

### 4.1 模拟器

```powershell
cd <repo>
$env:JAVA_HOME = '<JDK21>'
./gradlew.bat :app:installVerification -PapiBase=http://10.0.2.2:8080/api/v1
adb -s $env:ANDROID_SERIAL shell pm list packages io.whaletodo.app.verification
```

### 4.2 真机（与电脑同一热点）

```powershell
cd <repo>
$env:JAVA_HOME = '<JDK21>'
./gradlew.bat :app:installVerification -PapiBase=http://<电脑局域网IP>:8080/api/v1
adb -s $env:ANDROID_SERIAL shell pm list packages io.whaletodo.app.verification
```

如果 `installVerification` 找不到设备，可显式安装：

```powershell
./gradlew.bat :app:assembleVerification -PapiBase=http://10.0.2.2:8080/api/v1
$apk = (Get-ChildItem build/output/app/outputs/apk/verification/*.apk | Select-Object -First 1).FullName
adb -s $env:ANDROID_SERIAL install -r $apk
```

- 包名必须是 `io.whaletodo.app.verification`；正式包 `io.whaletodo.app` 与预览包 `io.whaletodo.app.preview` 不在本手册的安装/清理范围。
- debug/verification 允许 http；release/publicPreview 只接受 https，不能连本地 http。
- 不推荐改用正式 debug 包：会覆盖正式包数据，必须由设备所有者显式确认。

## 5. 推荐演示顺序

### 5.1 后端 demo 账号：登录、签到、钱包

```powershell
$base = 'http://127.0.0.1:8080/api/v1'
$body = @{ email = 'demo@example.invalid'; password = '<现场设置的演示密码>' } | ConvertTo-Json -Compress
$login = curl.exe -s -X POST -H 'Content-Type: application/json' --data $body "$base/auth/login" | ConvertFrom-Json
$token = $login.data.access_token
curl.exe -s -H "Authorization: Bearer $token" "$base/me"
curl.exe -s -X POST -H "Authorization: Bearer $token" "$base/rewards/daily/claim"   # 首次 201，当日再次 409
curl.exe -s -H "Authorization: Bearer $token" "$base/wallet"
curl.exe -s -H "Authorization: Bearer $token" "$base/wallet/ledger"
```

内存模式重启后该账号和签到数据会清空，但 demo 账号会重新 seed。

### 5.2 邮箱注册/找回（T44 outbox，仅 demo）

1. 启动时设置 `DEMO_EMAIL_OUTBOX`，按第 3 节 send-code → 读文件 → verify 换 ticket。
2. 用 ticket 注册：`POST /auth/register/email`；找回用 `purpose=reset` 再走一遍。
3. 注册/重置完成后用邮箱密码登录 App/接口。
4. **真实邮件投递仍未接入**：live/真库环境不要演示“收到邮件”；T44 只是 demo 本地文件收码，不是 SMTP。

### 5.3 AI 助手（#29 已合并，生产验收待完成）

- Android 客户端账户/AI 网络桥接已合并；本机 demo 可演示 App 登录后进入助手、展示 access/连接状态与失败提示。
- 真实 AI 调用需要生产账户/网关/积分预占；当前没有可用的生产验收账户，**不要演示“真实模型已闭环/AI 已上线”**。
- 详情与待验收边界见 #33 发布包文档；#33 仍在评审。

### 5.4 订单与 mock 支付（#23 已合并，T28 seed 3 商品）

```powershell
$base = 'http://127.0.0.1:8080/api/v1'
$token = '<登录后的 access_token>'
$products = curl.exe -s "$base/products" | ConvertFrom-Json
$productId = $products.data.products[0].product_id
$body = @{ product_id = $productId } | ConvertTo-Json -Compress
$order = curl.exe -s -X POST -H "Authorization: Bearer $token" -H 'Idempotency-Key: demo-order-1' `
  -H 'Content-Type: application/json' --data $body "$base/orders" | ConvertFrom-Json
```

- demo 内存模式有 3 个商品：`vip_7d`、`vip_30d`、`points_100`（T28 seed），可直接下单。
- mock 支付：`POST /payments/mock/webhook`；金额/币种必须匹配订单快照；同一 `event_id` 重放返回 replay，不重复发奖。
- 只有 mock 支付，没有真实支付/退款；客户端没有订单页面，用 curl 演示。

### 5.5 App 本地任务与提醒（#26 已合并）

1. 打开 App，新建任务（访客即可，不依赖登录）。
2. 编辑任务，打开「事务通知」；`method` 选消息或闹钟/两者，`timing` 选开始/结束/开始和结束。
3. 把开始时间设为 1 分钟后，保存；允许通知权限，等待通知。
4. 点击通知回 App；系统设置里确认两个渠道：
   - `task_reminders_message`：普通重要性
   - `task_reminders_alarm`：高重要性
   - 旧 `task_reminders` 不存在。
5. 切 guest/A/B 时只保留当前 owner 的 alarm（T38 已验证）；重启/时区重建受设备 OEM 影响，见第 7 节。

## 10. 停止与清理

```powershell
# 服务端：在运行窗口按 Ctrl+C
# App：默认保留数据，不做 pm clear / uninstall
```

- 默认只停服务端，保留 App 数据；内存模式重启后服务端数据自然清空。
- 只有确实需要清理一次性测试环境时，才显式清理 **verification 测试包**：

```powershell
adb -s $env:ANDROID_SERIAL shell pm clear io.whaletodo.app.verification
```

- **正式包 `io.whaletodo.app` 与预览包 `io.whaletodo.app.preview` 不得使用本手册的清理命令**。
- 演示结束删除 `outbox.jsonl`；不要把 `.env`、演示密码、access token、验证码或 outbox 路径提交进仓库。
