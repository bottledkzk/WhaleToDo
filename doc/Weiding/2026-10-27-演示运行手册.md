# 演示运行手册（2026-10-27）

适用：答辩现场、组内联调、给评审演示当前分支。  
基线：`main 3e7d712`；#23/#24/#25 的评审意见已修复、待复审；#26 提醒待评审，#27 本文档修复后待复审。合并状态以 GitHub 为准。

## 1. 前置检查

- Node.js 24（服务端 `node src/main.ts` 直接运行 TypeScript）
- JDK 21：`<JDK21>`
- Android SDK / `adb` 可用；仓库根目录记为 `<repo>`
- 默认使用 **verification 测试包** `io.whaletodo.app.verification`

### 1.1 选择设备（必须）

```powershell
adb devices
$env:ANDROID_SERIAL = '<目标设备序列号>'
adb -s $env:ANDROID_SERIAL get-state
```

- 多设备时所有 `adb` 命令都带 `-s $env:ANDROID_SERIAL`；
- `installVerification` 也使用同一个 `ANDROID_SERIAL`，不要依赖“默认设备”。

### 1.2 首次准备

```powershell
cd <repo>/server
npm ci --ignore-scripts --no-audit --no-fund
npx prisma generate --schema prisma/schema.prisma
```

内存模式仍建议执行 `prisma generate`，因为 `src/main.ts` 会导入 Prisma 仓储。

## 2. 服务端：内存模式启动

内存模式不配置 `DATABASE_URL`；重启后账户、签到、订单全部清空。  
如果 `server/.env` 里已有 `DATABASE_URL`，先临时注释掉或改名，否则会连接 Prisma/PostgreSQL，不是内存模式。

### PowerShell（Windows 演示机）

```powershell
cd <repo>/server
$env:NODE_ENV = 'demo'
$env:PAYMENT_PROVIDER = 'mock'
$env:MOCK_WEBHOOK_TOKEN = 'local-test-token'
$env:PORT = '8080'
$env:HOST = '0.0.0.0'       # 手机通过局域网访问时必须；只在本机可改回 127.0.0.1
$env:DATABASE_URL = ''      # 空 = 内存仓储
node src/main.ts
```

### Bash / Git Bash

```bash
cd server
NODE_ENV=demo PAYMENT_PROVIDER=mock MOCK_WEBHOOK_TOKEN=local-test-token \
  HOST=0.0.0.0 PORT=8080 DATABASE_URL= node src/main.ts
```

启动后检查：

```powershell
curl.exe -s http://127.0.0.1:8080/api/v1/health/live
# 期望 {"request_id":"...","data":{"status":"ok"}}
```

- `NODE_ENV=demo` 才允许 `PAYMENT_PROVIDER=mock`。
- 内存仓储只用于本地演示，不能当生产账户存储。
- 服务端日志会打印 `storage: memory(dev only)`，可据此确认没有连真库。

## 3. 构建并安装 App（verification 包）

默认只用测试包 `io.whaletodo.app.verification`，不覆盖正式包与预览包。

### 模拟器

```powershell
cd <repo>
$env:JAVA_HOME = '<JDK21>'

# 模拟器访问宿主机；真机把 10.0.2.2 换成电脑同一热点的局域网 IP
./gradlew.bat :app:installVerification -PapiBase=http://10.0.2.2:8080/api/v1

# 确认安装的是 verification 包
adb -s $env:ANDROID_SERIAL shell pm list packages io.whaletodo.app.verification
```

### 真机（与电脑同一热点）

```powershell
cd <repo>
$env:JAVA_HOME = '<JDK21>'
./gradlew.bat :app:installVerification -PapiBase=http://<电脑局域网IP>:8080/api/v1
adb -s $env:ANDROID_SERIAL shell pm list packages io.whaletodo.app.verification
```

如果 `installVerification` 找不到设备，可显式安装 verification APK：

```powershell
./gradlew.bat :app:assembleVerification -PapiBase=http://10.0.2.2:8080/api/v1
$apk = (Get-ChildItem build/output/app/outputs/apk/verification/*.apk | Select-Object -First 1).FullName
adb -s $env:ANDROID_SERIAL install -r $apk
```

- 包名必须是 `io.whaletodo.app.verification`；正式包 `io.whaletodo.app` 与预览包 `io.whaletodo.app.preview` 不在本手册的安装/清理范围。
- debug/verification 构建允许 http；release / publicPreview 只接受 https，不能连本地 http。
- 不推荐改用正式 debug 包：会覆盖正式包数据，必须由设备所有者显式确认；本手册默认步骤不使用。
- 构建前确认 `JAVA_HOME` 指向 JDK 21；APK 路径以 `build/output/app/outputs/apk/verification/` 实际输出为准。

## 4. 推荐演示顺序

### 4.1 后端账户/签到（main 已具备）

```powershell
$base = 'http://127.0.0.1:8080/api/v1'
$body = @{ username = 'demo_user'; password = 'S3cret-passw0rd' } | ConvertTo-Json -Compress
curl.exe -s -X POST -H 'Content-Type: application/json' --data $body "$base/auth/register"
$token = (curl.exe -s -X POST -H 'Content-Type: application/json' --data $body "$base/auth/login" | ConvertFrom-Json).data.access_token
curl.exe -s -H "Authorization: Bearer $token" "$base/me"
curl.exe -s -X POST -H "Authorization: Bearer $token" "$base/rewards/daily/claim"
curl.exe -s -H "Authorization: Bearer $token" "$base/wallet"
```

- 第一次签到 201；同一天第二次 409，余额不重复增加。
- 内存模式重启后，这个账号和签到记录会清空。

### 4.2 邮箱账户（#24 评审意见已修复、待复审；当前无 SMTP 不能实收验证码）

接口顺序：`/auth/email/send-code` → `/auth/email/verify` → `/auth/register/email` → `/auth/login {email,password}`；重置用 `purpose=reset` 再走一遍。完整命令见 `2026-10-26-答辩演示脚本.md` 第 3 节。

**限制**：当前没有 SMTP，`send-code` 只落验证码摘要，不会真的发邮件；没有 T18 的 seed/测试投递钩子时，`$code` 无法从现场取得。合并 #24 后，这段只讲设计/接口，等 T18 或 SMTP 接入后再现场跑通。

### 4.3 订单与 mock 支付（#23 评审意见已修复、待复审；T18 seed 商品后）

接口顺序：`GET /products` → `POST /orders` → `POST /payments/mock/webhook` → `GET /orders/:id` → `GET /me/entitlements`。完整命令见演示脚本第 4 节。

**限制**：

- #23 尚未合并，main 没有订单接口。
- 内存仓储的商品 Map 默认为空；T18 seed 之前 `GET /products` 返回空列表，无法下单。
- 订单/支付没有客户端 UI，只能用 curl 演示。

### 4.4 App 本地任务与提醒（#26 合并后；访客可演示）

1. 打开 App，新建一个任务（访客模式即可，不依赖登录）。
2. 编辑任务，打开「事务通知」；验证 `message` 与 `alarm/both` 两个渠道。
3. 把开始时间设为 1 分钟后，保存；允许通知权限，等待通知。
4. 点击通知回到 App；到系统设置确认：
   - `task_reminders_message`：普通重要性
   - `task_reminders_alarm`：高重要性
5. 重启模拟器或改时区，确认 BOOT/TIMEZONE/TIME_SET 重建。

**限制**：通知到点/重启重建还没有做真机验收；如果现场没弹，明确说“代码与编译已过，运行时验收待演示阶段”，不要改口成已验证。

### 4.5 App 登录/签到（#24 + #25 均评审意见已修复、待复审；且有 SMTP/seed 后）

当前没有演示账号 seed，且 App 登录走邮箱；无 SMTP 时现场无法完成注册/收码。T18 完成 seed 或临时投递钩子后，按「登录 → 签到 → 钱包/权益」演示；否则这部分用后端 curl 讲。

## 6. 停止与清理

```powershell
# 服务端：在运行窗口按 Ctrl+C
# App：默认保留数据，不做 pm clear / uninstall
```

- 默认收尾只停止服务端进程，**保留 App 数据**；内存模式重启后服务端数据自然清空。
- 只有确实需要清理一次性测试环境时，才显式清理 **verification 测试包**：

```powershell
# 仅测试包、仅测试设备；会清空该包数据
adb -s $env:ANDROID_SERIAL shell pm clear io.whaletodo.app.verification
```

- **正式包 `io.whaletodo.app` 与预览包 `io.whaletodo.app.preview` 不得使用本手册的清理命令**；它们可能包含正式记录或预览验收数据。
- 本手册不提供卸载正式包/预览包的步骤；如确需卸载，由设备所有者单独确认。
- 如果启动过 PostgreSQL 版本，另按部署文档清理；本手册只覆盖内存模式。
- 不要把 `.env`、`local-test-token`、access token 或演示密码提交进仓库。
