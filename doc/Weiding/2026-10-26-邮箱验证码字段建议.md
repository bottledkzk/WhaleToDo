# 邮箱验证码字段建议（Weiding → Bottledkzk）

日期：2026-10-26
依据：#14 评审中你冻结的安全边界。**本文只提字段与约束，不建表、不改迁移；迁移仍由你维护。**

## 1. 安全边界（按你的要求逐条对应）

| 要求 | 落地方式 |
| --- | --- |
| 6 位数字、5 分钟有效 | `code_hmac` + `expires_at = now() + interval '5 minutes'` |
| 同邮箱 60 秒 1 次、每小时 5 次 | 由 `email_throttle` 表原子计数（见 3） |
| 失败 5 次作废 | `attempts smallint` + `CHECK (attempts <= 5)`，校验失败自增，达 5 置 `consumed_at` |
| 按 IP / 账户 / 全局限流 | throttle 的 `scope` 三档：`email` / `ip` / `global` |
| HMAC 密钥持久且用途隔离 | `EMAIL_CODE_SECRET`，派生子密钥时拼 `:${purpose}`（与幂等键同一套做法） |
| purpose/email/有效期绑定 | 三者都进 HMAC 输入，改任意一项校验必失败 |
| 一次性消费 | `consumed_at` 非空即不可再用；消费用条件 UPDATE 保证原子 |
| verify 返回单次 ticket | 独立 `email_verify_tickets`，60 秒有效、绑定 purpose/email |
| register/reset 同事务校验消费 | 应用层：开事务 → 条件 UPDATE ticket → 业务写入 → 提交 |
| 重置撤销全部 auth_sessions | 同一事务内 `UPDATE auth_sessions SET revoked_at=now() WHERE user_id=$1 AND revoked_at IS NULL` |
| 不泄露邮箱是否存在 | 发送接口对"已注册/未注册"返回同一响应与同一耗时；校验失败也只回 `code_invalid` |
| console 不打印明文码 | console provider 只打印 `email=<hint> code=<***>`，明文仅存在于内存变量 |
| SMTP 受理≠投递 | provider 接口返回 `accepted`（SMTP 250）与 `delivered` 分开记录，UI 只承诺"已发送请求" |

## 2. 表一：`email_verifications`

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `id` | uuid | 主键 |
| `purpose` | varchar(16) | NOT NULL, `CHECK (purpose IN ('register','reset','bind'))` |
| `email_normalized` | varchar(254) | NOT NULL（`lower(trim())` 后写入，**不做 ILIKE 查询**） |
| `code_hmac` | char(64) | NOT NULL（HMAC-SHA256 十六进制） |
| `attempts` | smallint | NOT NULL DEFAULT 0, `CHECK (attempts >= 0 AND attempts <= 5)` |
| `expires_at` | timestamptz(3) | NOT NULL, `CHECK (expires_at > created_at)` |
| `consumed_at` | timestamptz(3) | 可空（非空=已用完/已作废） |
| `created_at` | timestamptz(3) | NOT NULL DEFAULT now() |

索引：
- `(email_normalized, purpose, created_at DESC)` —— 取最新一条做校验
- 部分唯一索引 `UNIQUE (email_normalized, purpose) WHERE consumed_at IS NULL` ——
  **同一邮箱同一用途只允许一条有效码**，发新码时把旧码置 `consumed_at`（同事务）

## 3. 表二：`email_throttle`（限流计数，可按需换共享存储）

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `scope` | varchar(8) | NOT NULL, `CHECK (scope IN ('email','ip','global'))` |
| `scope_key` | varchar(128) | NOT NULL（邮箱归一化值 / IP 的 HMAC / 固定 `'all'`） |
| `window_start` | timestamptz(3) | NOT NULL |
| `count` | smallint | NOT NULL DEFAULT 0, `CHECK (count >= 0)` |
| `updated_at` | timestamptz(3) | NOT NULL DEFAULT now() |

主键 `(scope, scope_key, window_start)`。
限流写入用一条原子 upsert：

```sql
INSERT INTO email_throttle (scope, scope_key, window_start, count)
VALUES ($1, $2, date_trunc('hour', now()), 1)
ON CONFLICT (scope, scope_key, window_start)
DO UPDATE SET count = email_throttle.count + 1, updated_at = now()
RETURNING count;
```

返回 `count > 5` 即拒绝（邮箱维度另加 60 秒间隔检查：看最近一条 `email_verifications.created_at`）。

## 4. 表三：`email_verify_tickets`

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `id` | uuid | 主键 |
| `token_hmac` | char(64) | NOT NULL UNIQUE（只存摘要） |
| `purpose` | varchar(16) | NOT NULL, 同上 CHECK |
| `email_normalized` | varchar(254) | NOT NULL |
| `expires_at` | timestamptz(3) | NOT NULL（建议 60 秒） |
| `consumed_at` | timestamptz(3) | 可空 |
| `created_at` | timestamptz(3) | NOT NULL DEFAULT now() |

消费必须条件更新，防止并发双花：

```sql
UPDATE email_verify_tickets
   SET consumed_at = now()
 WHERE token_hmac = $1 AND consumed_at IS NULL AND expires_at > now()
RETURNING purpose, email_normalized;
```

影响 0 行 → 拒绝（ticket 过期/已用/不存在，对外统一 `code_invalid`）。

## 5. 与 `users.email` 的关系

`users.email` 是已有字段（`lower(email)` 部分唯一索引）。写入时机：

- `purpose=register`：注册事务内，ticket 消费成功后才写 `email`
- `purpose=bind`：登录态下绑定，需 ticket 的 `email_normalized` 与提交邮箱一致
- `purpose=reset`：只用于身份证明，不修改 email 字段

**不允许**客户端直接提交 `email` 就写库，必须伴随 ticket 消费。

## 6. RLS 与权限（请你按现有约定落）

这三张表是**服务内部表**，没有 `user_id`，我建议：

- 不启用 RLS（不按用户分区），但**只给 `whaletodo_app` 授予 SELECT/INSERT/UPDATE**，
  不给 DELETE（保留审计），由应用侧把过期记录交给你定期清理
- 邮箱与 IP 一律存**归一化值或 HMAC**，不存明文 IP

## 7. 接口（我实现，字段以上表为准）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/v1/auth/email/send-code` | `{purpose, email}`；响应一律 202，不区分邮箱是否已注册 |
| POST | `/api/v1/auth/email/verify` | `{purpose, email, code}` → `{ticket, expires_in}`；失败统一 `code_invalid` |
| POST | `/api/v1/auth/register` | 增加可选 `email_ticket`；有 ticket 则同事务消费并写 `email` |
| POST | `/api/v1/auth/password/reset` | `{email_ticket, new_password}`；同事务消费 + 撤销该用户全部会话 |
