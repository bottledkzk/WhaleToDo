### 踩坑记录（重要，别重犯）

1. **不要用 PowerShell 做多行代码替换**
   PowerShell 里 `"`n"` 在单引号 here-string 中会被写成**字面量 `\n`**，直接破坏 TS 文件。
   今天两次因此把 `memory.ts` / `sync.ts` 改坏，只能 `git checkout -- .` 回滚。
   **正确做法**：把补丁写成 `.mjs` 文件（用 node 执行，字符串按 JS 语义处理），或直接用 edit 工具。

2. **锚点匹配失败要立刻停下**
   我的补丁脚本把"未匹配"也打印成成功，导致误以为改好了、实际没改，
   后续判断又被脏内容污染。补丁脚本必须在未匹配时抛错或返回非零。

3. **多字节 payload 必须按 UTF-8 字节判断**
   `String.length` 是 UTF-16 码元数，30000 个汉字会通过字符检查却撞 PostgreSQL 的
   `octet_length <= 65536`（字节）约束。用 `Buffer.byteLength(x, 'utf8')`。

4. **GitHub 匿名 API 限额每小时 60 次**
   频繁轮询会耗尽。查"是否合并"用 `git ls-remote` + `git merge-base --is-ancestor`，
   不消耗 API；需要读评审内容时再调 API，或等一小时。

5. **`from-sync` 适配器容易漏方法**
   新增仓储方法后必须同步转发（`claimDailyReward`、`listLedger`、`dailyStatus`、
   `pushSyncBatch`、`pullSyncChanges` 都曾因漏转发导致默认内存路径 500）。
   每个新方法都补一条"内存路径 HTTP 测试"。
