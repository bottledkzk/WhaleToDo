## 3. 自己发现并修掉的隐患

**`ILIKE` 通配符越权风险**：适配器最初用 Prisma 的 `mode: 'insensitive'` 查用户名，生成 `ILIKE`。
但用户名允许下划线（`^[A-Za-z0-9_]{3,32}$`），`_` 在 LIKE 中是通配符 —— 查 `alice_01` 可能匹配到
`aliceX01` 的账号，导致登录到他人账户。已改为 `lower(username) = lower($1)`，与数据库
`users_username_ci` 表达式索引同规则。

**幂等键跨用户碰撞**：幂等回执主键是 `(scope, key)`，无 `user_id` 列。若 scope 不含归属，
两个用户同 key 会互相顶掉（后到者拿到前者的响应）。已约定 scope 写成 `order:<userId>` 形式，
并作为评审问题提交给同事确认。

**测试类型拖累 CI**：`rewards/billing/sync` 三个测试文件用了 `Parameters<inject>[0]`，
会选中零参数重载导致 47 条类型错误。虽不影响 `node --test` 运行，但会让 CI 的 `typecheck` 挂，
已全部改为 `light-my-request` 的 `InjectOptions`。

每一条都补了回归测试，第二轮获得 `APPROVED`。

### 7.2 主动做真库集成测试，而不是只跑内存单测

内存实现能过的语义，换到真实 PostgreSQL + 受限运行角色上往往会碎。这一轮被评审抓出并修复的真问题：

- **42501 权限失败**：Prisma 把 `role`/`status` 的字面默认值也写进 INSERT，而运行角色没有这两列写权限
  → 改为参数化 INSERT 只列允许字段，让数据库默认值生效（**没有扩大授权来绕过**）
- **RLS 上下文缺失**：`user_settings` 启用了行级安全，插入前必须在同一事务内
  `set_config('app.user_id', <新用户 id>, true)`
- **P2010 而非 P2002**：原生 `$executeRaw` 的唯一冲突被 Prisma 包装成 `P2010` + `meta.code=23505`，
  只认 `P2002` 会导致并发注册直接 500

为此新增 `integration/account-repository.test.ts`，在 CI 的 `database` job 里
用 `whaletodo_app` 受限角色实例化真实仓储，验证注册、RLS、回执不覆盖、并发轮换。

### 7.3 并发与幂等边界被真实探针验证

评审用真实 PG 双 HTTP 探针复现了三类边界问题，逐一修复并补测试：

| 场景 | 修复 |
| --- | --- |
| 同 body/key 双并发注册 → `[201, 500]` | 唯一冲突精确识别 + 优先重读赢家回执，同指纹返回首次 201 |
| 过期回执替换被并发覆盖 | 改为条件 UPDATE（`WHERE expires_at <= now()`），影响 0 行即放弃 |
| 组合注册事务撞物理存在的过期行 | 事务内条件 UPDATE 抢占同一行，不再 `create` 撞唯一键 |

新增 `integration/register-concurrency.test.ts`：同体并发**两个都是 201 且同一用户**、
同 key 异体 409、不同 key 同用户名 409，全部断言**不出现 500**。

## 8. 架构补充：主服务与 AI 网关是两个进程

```
npm start        → src/main.ts     账户 / 签到 / 钱包 / 流水 / 同步
npm run ai:start → src/ai/main.ts  AI 网关（同事负责）
```

- 两者**共用同一个 PostgreSQL**，也共用同一套 access token：AI 侧逐请求查 `auth_sessions`
  并校验 `revoked_at` / `access_expires_at` / `users.status`，所以会话撤销后 AI 请求立即 401
- 实测确认：主服务端口上访问 `/api/v1/ai/*` 返回"未知端点"（404），说明 AI 路由确实只在
  AI 进程上暴露；两侧职责边界清晰，不存在"账户服务被 AI 模块侵入"的情况
- 已知边界：已发往模型供应商的在途请求不会因注销回滚费用，这一点与同事确认过
