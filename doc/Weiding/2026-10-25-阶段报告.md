## 3. 自己发现并修掉的隐患

**`ILIKE` 通配符越权风险**：适配器最初用 Prisma 的 `mode: 'insensitive'` 查用户名，生成 `ILIKE`。
但用户名允许下划线（`^[A-Za-z0-9_]{3,32}$`），`_` 在 LIKE 中是通配符 —— 查 `alice_01` 可能匹配到
`aliceX01` 的账号，导致登录到他人账户。已改为 `lower(username) = lower($1)`，与数据库
`users_username_ci` 表达式索引同规则。

**幂等键跨用户碰撞**：幂等回执主键是 `(scope, key)`，无 `user_id` 列。若 scope 不含归属，
两个用户同 key 会互相顶掉（后到者拿到前者的响应）。已约定 scope 写成 `order:<userId>` 形式，
并作为评审问题提交给同事确认。

**测试类型拖累 CI**：`rewards/billing/sync` 三个测试文件用了 `Parameters<inject>[0]`，
会选中零参数重载导致 47 条类型错误。虽不影响 `node --test` 运行，但会让 CI 的 `typecheck` 挂，
已全部改为 `light-my-request` 的 `InjectOptions`。

同事的 PR #3 提供了权威 schema（16 张表、4 个迁移、RLS、受限角色、AI 网关）。我这边的对齐动作：

| 他的约束 | 我的实现 |
| --- | --- |
| `lower(username)` / `lower(email)` 唯一索引 | 仓储用 `lower() = lower()` 精确匹配 |
| `password_hash` CHECK 限定 `scrypt$`/`$argon2id$` | 异步 scrypt 输出 `scrypt$N$r$p$salt$hash`，格式吻合 |
| `demo_slot` 1~10，槽满抛 `DEMO_USER_LIMIT`（23514） | 建号失败可映射为 409「演示容量已满」，不当作 500 |
| 注册需建零余额钱包 + 默认设置 | `createUser` 中 `users` + `point_wallets` + `user_settings` 同事务 |
| 刷新轮换需同事务 | `rotateSession`：撤销旧（命中必须为 1 行）+ 插新（同 family） |
| 内容表 RLS 需 `set_config('app.user_id',…,true)` | 账户/会话表不套内容 RLS；后续内容仓储在事务内设置 |

我没有另建余额表、没有自造 schema：建议稿已关闭，一切以他的迁移为准。
