演示：

```powershell
$base = 'http://127.0.0.1:8080/api/v1'
$password = '<现场设置的演示密码>'
$body = @{ email = 'demo@example.invalid'; password = $password } | ConvertTo-Json -Compress
$login = curl.exe -s -X POST -H 'Content-Type: application/json' --data $body "$base/auth/login" | ConvertFrom-Json
$token = $login.data.access_token
curl.exe -s -H "Authorization: Bearer $token" "$base/me"
curl.exe -s -X POST -H "Authorization: Bearer $token" "$base/rewards/daily/claim"   # 首次 201，再次 409
curl.exe -s -H "Authorization: Bearer $token" "$base/wallet"
curl.exe -s -H "Authorization: Bearer $token" "$base/wallet/ledger"
```

讲解要点：

- 注册只返回 `(id, username, display_name)`；运行角色没有写 schema 权限。
- 签到第二次返回 409，余额不重复增加；唯一性由数据库约束兜底。
- 流水含 `balance_after` 与 ISO8601 时间，可直接对账。

```powershell
# 启动 demo 时加：
$env:DEMO_EMAIL_OUTBOX = '<已有父目录>\outbox.jsonl'
```

现场流程：

**注册（未注册邮箱，purpose=register）**

```powershell
$base = 'http://127.0.0.1:8080/api/v1'
$email = 'demo-register@example.invalid'   # 未注册；不要用 T28 seed
$body = @{ email = $email; purpose = 'register' } | ConvertTo-Json -Compress
curl.exe -s -X POST -H 'Content-Type: application/json' --data $body "$base/auth/email/send-code"

# 读 outbox 最后一行，不打印/不贴 code
$entry = Get-Content -LiteralPath $env:DEMO_EMAIL_OUTBOX | Select-Object -Last 1 | ConvertFrom-Json
$code = $entry.code

$body = @{ email = $email; purpose = 'register'; code = $code } | ConvertTo-Json -Compress
$verify = curl.exe -s -X POST -H 'Content-Type: application/json' --data $body "$base/auth/email/verify" | ConvertFrom-Json
$ticket = $verify.data.ticket

$body = @{ email = $email; ticket = $ticket; password = '<演示密码>'; display_name = '演示鲸鱼' } | ConvertTo-Json -Compress
curl.exe -s -X POST -H 'Content-Type: application/json' --data $body "$base/auth/register/email"

$body = @{ email = $email; password = '<演示密码>' } | ConvertTo-Json -Compress
curl.exe -s -X POST -H 'Content-Type: application/json' --data $body "$base/auth/login"
```

**找回（已注册邮箱，purpose=reset）**

```powershell
$base = 'http://127.0.0.1:8080/api/v1'
$email = 'demo@example.invalid'   # seed 账户；或刚注册的账户
$body = @{ email = $email; purpose = 'reset' } | ConvertTo-Json -Compress
curl.exe -s -X POST -H 'Content-Type: application/json' --data $body "$base/auth/email/send-code"

$entry = Get-Content -LiteralPath $env:DEMO_EMAIL_OUTBOX | Select-Object -Last 1 | ConvertFrom-Json
$code = $entry.code
$body = @{ email = $email; purpose = 'reset'; code = $code } | ConvertTo-Json -Compress
$ticket = (curl.exe -s -X POST -H 'Content-Type: application/json' --data $body "$base/auth/email/verify" | ConvertFrom-Json).data.ticket

$body = @{ email = $email; ticket = $ticket; password = '<现场设置的新密码>' } | ConvertTo-Json -Compress
curl.exe -s -X POST -H 'Content-Type: application/json' --data $body "$base/auth/password/reset"

# 新密码应登录成功；旧密码应返回 401
$body = @{ email = $email; password = '<现场设置的新密码>' } | ConvertTo-Json -Compress
curl.exe -s -X POST -H 'Content-Type: application/json' --data $body "$base/auth/login"
```

- 注册必须用未注册邮箱；找回必须用已注册邮箱（seed 或刚注册），两者不要混用同一个未注册邮箱。
- `send-code`/`verify` 的 `purpose` 分别与注册/找回一致；reset 成功返回 204 后，必须用新密码
  登录成功、旧密码失败；旧 refresh/session 由服务端撤销，必要时补验 401。
- **MemoryRepository 防枚举**：合法 reset ticket 遇到不存在邮箱会返回 204/ok，但不会创建账户
  或改密码；这是“表面成功”，不能作为找回通过，也不能用未注册邮箱演示 reset。
- outbox 每行 JSON `{time,purpose,email,code}`，目标权限 `0600`；父目录必须已存在，不自动建目录。
- 仅 `NODE_ENV=demo` 且无 `DATABASE_URL` 可用；production/DB 模式启动拒绝。
- 写失败返回 500，不会 `sent:true`；日志/响应/DB 不落明文 code。
- 演示结束删除 outbox；**不要提交文件、不要贴 code**。
- 真实 SMTP：无；账户 API 尚未发布，当前不能完成真实邮件注册/找回；T44 仅 demo 本地文件收码。

## 4. 订单与 mock 支付（#23 已合并，约 2 分钟）

```powershell
$base = 'http://127.0.0.1:8080/api/v1'
$token = '<登录后的 access_token>'
$products = curl.exe -s "$base/products" | ConvertFrom-Json
$productId = $products.data.products[0].product_id
$body = @{ product_id = $productId } | ConvertTo-Json -Compress
$order = curl.exe -s -X POST -H "Authorization: Bearer $token" -H 'Idempotency-Key: demo-order-1' `
  -H 'Content-Type: application/json' --data $body "$base/orders" | ConvertFrom-Json
$orderId = $order.data.order.id
$amount = $order.data.order.amount_minor
$currency = $order.data.order.currency

$body = @{ event_id = 'evt-demo-1'; order_id = $orderId; status = 'succeeded'; amount_minor = $amount; currency = $currency } | ConvertTo-Json -Compress
curl.exe -s -X POST -H "Authorization: Bearer $token" -H 'Content-Type: application/json' --data $body "$base/payments/mock/webhook"
```

- demo 内存模式有 3 个商品（T28 seed），可直接下单。
- 客户端只传 `product_id`，金额/币种/VIP 天数来自服务端商品快照。
- 同一 `event_id` 重放不重复发奖；跨订单复用 409；VIP 到期时间叠加而不是覆盖。
- 只有 mock 支付，没有真实支付/退款；客户端无订单页面，用 curl 演示。

4. 等待通知；点击通知回 MainActivity；系统设置确认渠道：

5. 切 guest/A/B：只保留当前 owner 的 alarm（T38 为 Weiding 侧真机实测；

## 9. 常见提问与答法（2 分钟）

| 老师可能问 | 回答 |
| --- | --- |
| 密码怎么存？ | scrypt + 随机盐，异步计算不阻塞事件循环；只存摘要，恒定时间比较。 |
| 会话怎么失效？ | 不透明刷新令牌存 SHA-256 摘要，15 分钟 access / 30 天 refresh；刷新轮换，重放检测后整链撤销。 |
| 重复提交怎么办？ | `Idempotency-Key` + 服务端 scope：同键同体返回首次结果，同键异体 409。 |
| 并发安全吗？ | 关键路径有真库并发测试：签到、注册、刷新轮换、同步批次、邮箱并发、订单支付。 |
| 数据隔离怎么保证？ | 内容表 RLS，事务内 `set_config('app.user_id', …)`，应用层再校验归属。 |
| 没有 SMTP 怎么注册？ | 仅 demo 用 T44 本地 outbox 收码；账户 API 未发布，live/真库如实说“邮件未接入，不能完成真实注册”。 |
| 订单金额怎么防篡改？ | 客户端只传 `product_id`；下单写不可变快照，支付校验金额/币种都读快照。 |
| 重复支付回调怎么处理？ | `(provider,event_id)` 唯一键 + 状态机；同订单 replay 不重复发奖，跨订单 409。 |
| 提醒重启后还在吗？ | 已调度 requestCode 存 prefs；保存/完成/恢复/时区变化都 resync；BOOT/TIMEZONE/TIME_SET 由 Receiver 重建。**vivo 实测会丢 BOOT，属 OEM 限制（T38 Weiding 侧真机记录；Bottledkzk #26 只有 API36 模拟器合成检查）**。 |
| AI 真的能用吗？ | 客户端桥接已合并；已有 PostgreSQL 与旧 AI 网关运行，账户 API 未发布，#33 新版网关/迁移/生产 APP 闭环待发布/验收；不声称已闭环。 |
