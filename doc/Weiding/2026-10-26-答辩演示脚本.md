# 答辩演示脚本（Weiding 负责部分）

目标：8 分钟内讲清楚"账户 → 签到 → 同步"这条主线，每一步都有可复现的证据。

## 0. 一句话开场（30 秒）

> 我负责后端账户与业务接口：账户注册登录、签到积分、同步。
> 代码在 `server/`，有 137 项单元/接口测试和一套跑在真实 PostgreSQL 上的集成测试。

## 1. 架构先说清楚（1 分钟）

两个进程、同一个数据库：

```
npm start        → src/main.ts     账户 / 签到 / 钱包 / 流水 / 同步
npm run ai:start → src/ai/main.ts  AI 网关（同事负责）
```

- 两者共用 PostgreSQL 与同一套 access token（AI 侧逐请求查 `auth_sessions` 校验撤销与过期）
- 客户端只跟主服务打交道，AI 侧只接受已认证请求

## 2. 演示主服务（3 分钟）

```bash
cd server
npm ci --ignore-scripts && npx prisma generate
npm run typecheck      # 期望：0 诊断
npm test               # 期望：137 项全过
PORT=8080 npm start
```

另开一个终端，按顺序发请求（`PowerShell`）：

```powershell
# 注册
curl.exe -s -X POST -H 'Content-Type: application/json' `
  --data '{"username":"demo_user","password":"S3cret-passw0rd"}' `
  http://127.0.0.1:8080/api/v1/auth/register

# 登录拿 token
curl.exe -s -X POST -H 'Content-Type: application/json' `
  --data '{"username":"demo_user","password":"S3cret-passw0rd"}' `
  http://127.0.0.1:8080/api/v1/auth/login

# 用 token 查询自己
curl.exe -s -H 'Authorization: Bearer <access_token>' http://127.0.0.1:8080/api/v1/me

# 签到（第一次 201，第二次 409）
curl.exe -s -X POST -H 'Authorization: Bearer <access_token>' `
  http://127.0.0.1:8080/api/v1/rewards/daily/claim

# 钱包与流水
curl.exe -s -H 'Authorization: Bearer <access_token>' http://127.0.0.1:8080/api/v1/wallet
curl.exe -s -H 'Authorization: Bearer <access_token>' http://127.0.0.1:8080/api/v1/wallet/ledger
```

讲解要点：
- 注册返回的用户只含 `(id, username, display_name)`，角色/状态由数据库默认值决定（运行角色无写权限）
- 签到第二次返回 **409 CONFLICT**，余额不变——并发靠数据库唯一键，不是应用层判断
- 流水返回 `balance_after` 与 `created_at`（ISO8601），可直接对账

## 3. 展示真库测试（2 分钟）

打开 Actions 里 `database` job 的日志，指出这几条：

| 用例 | 断言 |
| --- | --- |
| 并发 5 次签到 | 只有 1 次成功，流水 1 条，余额 30 |
| 同毫秒 3 条流水 limit=2 | 两页 `[2,1]`，ID 不重不漏 |
| 注册并发同体 | 两个都是 201 且同一用户（唯一冲突转幂等重放） |
| 跨账户 | B 拉不到 A 的流水与变更 |

一句话总结：**内存测试能过，不代表真库能过；所以我们专门做了一套跑在真实 PostgreSQL + 受限角色上的测试。**

## 4. 展示可观测性（30 秒）

```bash
LOG_LEVEL=info LOG_FILE=./access.log PORT=8080 npm start
```

日志每条一行：

```json
{"event":"access","request_id":"…","method":"POST","path":"/api/v1/auth/login",
 "status":200,"duration_ms":134.5,"user_id":null,"error_code":null}
```

要点：不含 `Bearer`、不含 `access_token`（鉴权头与响应体都不落日志），401 时会带 `error_code`。

## 5. 常见提问与答法（2 分钟）

| 老师可能问 | 回答 |
| --- | --- |
| 密码怎么存？ | scrypt + 随机盐，异步计算不阻塞事件循环；只存摘要，登录比较用恒定时间比较 |
| 会话怎么失效？ | 不透明刷新令牌存 SHA-256 摘要，15 分钟 access / 30 天 refresh；刷新时轮换，检测到重放就整链撤销 |
| 重复提交怎么办？ | `Idempotency-Key` + 服务端 scope：同键同体返回首次结果，同键异体 409 |
| 并发安全吗？ | 关键路径都有真库并发测试：签到、注册、刷新轮换、同步批次 |
| 数据隔离怎么保证？ | 内容表启用 RLS，事务内 `set_config('app.user_id', …)`，同时应用层还做归属校验（双重） |
| 表结构谁维护？ | 同事统一维护 schema 与迁移，我提字段建议并实现 API 业务 |
