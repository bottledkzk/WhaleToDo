# WhaleToDo 目标功能文档

版本：0.1 草案　日期：2026-10-22　状态：供团队讨论范围与后续分工。

## 1. 产品目标

面向有学习、工作和个人安排的 Android 用户，把“记下来—看清楚—安排好—做完—回看—分享”串成一个流程。核心能力在无网络、未登录或未配置模型时仍可使用。应用不依赖特定手机品牌的专属服务。

首轮应能展示一个完整软件流程，并让每位成员解释自己负责的代码、数据流、技术选择和测试。当前文档描述目标，不代表所有功能已经实现。

## 2. 用户与主要场景

| 场景 | 需求 | 产品响应 |
| --- | --- | --- |
| 临时想到一件事 | 不希望填写长表单 | 输入标题即可保存到收集箱，稍后补时间和工时 |
| 今天事情很多 | 想知道任务实际落在什么时候 | 日／周计划与截止／负荷概览，区分待办和已安排块 |
| 插入紧急工作 | 不想手动重排全部任务 | 明确预览新增、移动、保留和未安排量 |
| 长期项目 | 短期行动不能脱离长期目标 | 长期／分阶段目标，阶段工时合计且不重复占用 |
| 没按计划完成 | 希望调整而不是丢失历史 | 补记完成、自评、重排剩余工作，保留过去记录 |
| 需要陪伴或整理表达 | 希望获得建议、日记或分享文案 | AI 提案与草稿，用户核对后采用 |
| 更换手机 | 希望数据可恢复且私人内容不外泄 | 本地备份先行，后续账户隔离与可选择同步 |

## 3. 范围与优先级

P0：首个可演示闭环；P1：主要产品增强；P2：在基线稳定后评估。

### F01 快速记录与整理（P0）

- 标题必填，截止、预计工作量、重要度、标签和备注可后补；未补全的事项保留在收集箱，不能猜测工时自动排程。
- 提供完成、撤销完成、编辑、归档、搜索和标签过滤；删除有确认或可撤销路径。
- 工时支持分钟／小时／天，明确一天表示24小时预算，不等于每天都可连续工作24小时。
- 支持短期、长期和最多16阶段目标；长期结束可选，阶段可编辑名称、起止与预算。
- 验收：最短路径创建、空标题拒绝、编辑／完成后重启保留、搜索能到达全部记录；重复点击不重复创建。

### F02 直观 Todo 分布（P0／P1）

- P0：今日清单、日计划时间线、未排事项和完成状态。
- P1：周时间表、月日历、长期月／周切换与负荷图；尺度使用列表选择，所有视图读取同一数据源。
- 标题优先可读，短时间块有最小展示高度；展示空间变化不能修改实际起止。重叠事件分栏，完整信息可在详情查看。
- 颜色、文字、图标共同区分任务、忙碌、固定、完成与逾期，不能只靠颜色判断。
- 验收：列表与日／周／月统计守恒，跨午夜正确拆分；大字体、暗色和窄屏仍能操作。

### F03 自动协调安排（P0）

- 输入截止、最早开始、预计工时、重要度、拆分策略；空闲支持每周和特定日期，忙碌支持一次和重复。
- 课业或工作事项可设置自身执行窗口；相邻、重叠区间按并集合并，真实空隙保留。
- 排程遵守可用时间、忙碌、截止、父目标约束，不把已完成预算再排一次；保留固定、过去与进行中安排。
- 临时插入后预览变化，确认应用；不能安排时显示未排分钟与可采取的调整，不越过截止凑满。
- 自动安排是可解释的启发式方案，不承诺数学上的全局最优。
- 验收：无重叠、工时守恒、截止和保护约束、连续任务不可跨空隙、重复输入幂等、跨尺度一致。

### F04 提醒（P0／P1）

- 本地通知与提前量为基础；精确提醒按系统能力和用户授权设计，不能把后台定时工作当精确闹钟。
- 任务改期、完成、撤销、删除后同步更新或取消提醒，重启和时区变化后重新核对。
- 权限拒绝、电池限制、勿扰等限制按需解释，并提供对应系统设置入口；不反复骚扰授权。
- 小米14 Pro 是首个目标真机，另覆盖不同 Android 版本及至少一种其他厂商设备／模拟配置。
- 验收：前台、后台、锁屏、重启、拒绝权限、重复提醒、改期取消各自记录，不用单次通知成功替代全部场景。

### F05 打卡与复盘（P0／P1）

- 完成可以记录实际时间、五档自评和可选反思；允许补记与更正，计划工时和实际完成分开统计。
- P0：每日完成条目与记录；P1：连续天数、阶段进度、周期报告和本地日记。
- AI 可根据明确选择的真实记录生成日记／复盘草稿；不得虚构经历，用户可编辑、保存或丢弃。
- 验收：更正后统计重算、跨日和时区口径明确、不重复累计，删除任务不静默毁掉完成历史。

### F06 AI 对话 Agent 与辅助（P1）

- 通用模型配置：HTTPS接口、协议、提供方规定的模型ID、凭据；支持OpenAI兼容和Anthropic格式，不绑定手机品牌。
- 会话新建、历史、搜索、继续、归档／删除，输入与会话隔离；功能从同一对话入口选择。
- 辅助模式：拆解目标、生成待办、安排咨询、受控重排、周期复盘、日记、打卡短句及分享文字。
- 修改操作采用“结构化提案—本地校验—用户预览确认—整批提交”，不能让模型绕过固定、完成、权限或截止规则。
- 摘要共享可关闭；明确本次发送范围，默认不发送凭据、私人备注、完整数据库或账号令牌。
- 空正文、截断、格式错误、超时、鉴权失败和额度不足分别提示；仅在明确的格式错误下有限纠正，不无限重试或自动扣费。
- 验收：无凭据也能完成本地流程，模拟服务与真实服务分开验证；真实模型新增或修改任务必须经过确认，失败不能部分落库。

### F07 社交分享（P1）

- Android系统分享面板：向用户选择的软件分享文字或图片，不默默向社交平台发消息。
- 生成可预览的今日安排／打卡卡片，支持保存图片；主题、日期和内容可选，默认不包含备注、地点、账号等敏感字段。
- AI短句是可编辑草稿；发布前必须由用户在目标应用确认。
- 网站公开分享链接作为P2，默认私密或有明确失效设置；首轮不做复杂社交关系链、即时聊天或内容推荐。
- 验收：分享文字、图片、取消、无可用目标应用、存储失败、撤销链接和隐私字段过滤分别验证。

### F08 账户、同步与下载网站（P1，依赖服务环境）

- 本地访客可用；后续支持注册、登录、退出、找回、会话撤销、账户数据隔离和注销说明。
- 服务端负责密码安全、身份验证、数据归属和令牌生命周期；客户端不保存明文密码，不把模型凭据放在公开前端。
- 同步需明确冲突处理、离线修改、重试和多设备口径；账户退出不能把A账户数据展示给B账户。
- 下载网站首先提供真实功能、版本状态、APK下载、SHA256、安装说明、变更记录和项目入口。
- 域名、服务器和注册系统后续配置；购买、DNS、邮件服务及生产发布单独安排。未上线前不提供假注册／假登录成功。
- 验收：下载链接可读回并验证文件，登录错误／过期／退出／跨账户访问被正确处理，服务故障不阻止本地核心使用。

### F09 UI、便捷操作与设备适配（跨阶段）

五个主要目的地为今日、计划、事项、伙伴、我的；快速新增可从常用页面触达。高频操作保持短路径，低频设置集中管理。统一鲸鱼品牌、留白密度、字号、状态和错误反馈；亮／暗／系统主题，壁纸和伙伴作为可关闭的个性化增强，不盖住关键操作。

适配目标：Android API26起，编译／目标SDK36的首轮基线；720—1440宽手机、大字体、手势导航、安全区、深色、横屏／大屏按矩阵验证。系统版本与设备实际结果以环境记录为准，不能按型号推断用户当前系统。

## 4. 关键数据与边界

| 对象 | 职责 |
| --- | --- |
| Task／Goal／Stage | 事项与预算，父子关系、截止、最早开始、重要度、归档 |
| Availability／BusyEvent | 可用时间与固定占用，自定义窗口和重复规则 |
| PlanBlock | 实际安排区间、固定、完成关联与修订号 |
| CheckIn | 实际完成、自评和反思，与计划量分开 |
| Conversation／Proposal | 对话上下文、可确认操作、版本与执行回执 |
| Account／SyncState | 账户归属、会话状态和同步版本，不包含明文密码 |
| ShareDraft | 明确选择的分享内容、图片和隐私选项 |

所有时间按明确时区转换，持久层保留稳定ID与版本。导入、恢复和AI提案先校验，事务失败保留原数据；备份不含凭据。任何自动推断都需可见、可修改，不能把猜测当成用户确定信息。

## 5. 阶段范围与非目标

首个可演示版本聚焦本地快速记录—安排—完成—重启保持；后续迭代再接入完整日历、AI、提醒适配、分享和账户。首轮不做团队协同编辑、复杂社区、自动社交发布、付费订阅、任意代码Agent或服务器代持第三方模型Key。

本文件不是成员分工单。每项功能后续应拆为Issue，补负责人、接口、验收、依赖和评审人，再由本人确认。
