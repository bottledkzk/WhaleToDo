# WhaleToDo 目标功能文档

版本：0.5　日期：2026-10-31　状态：公开0.5.4预览版已交付；保留现有预览日历、VIP主动日程备份／同步与账号资料跟随，设备范围见[交付回执](../Bottledkzk/2026-10-31-0.5.4交付与验收.md)；分工见《分工与协作方案》。

## 1. 产品目标

面向有学习、工作和个人安排的 Android 用户，把“记下来—看清楚—安排好—做完—回看—分享”串成一个流程。本地记录、计划和打卡在离线或未登录时仍可使用；所有AI服务必须登录，并由服务器校验积分与权限后转发模型请求。应用不依赖特定手机品牌的专属服务。

首轮应能展示一个完整软件流程，并让每位成员解释自己负责的代码、数据流、技术选择和测试。当前文档描述目标，不代表所有功能已经实现。

## 2. 用户与主要场景

| 场景 | 需求 | 产品响应 |
| --- | --- | --- |
| 临时想到一件事 | 不希望填写长表单 | 输入标题即可保存到收集箱，稍后补时间和工时 |
| 今天事情很多 | 想知道任务实际落在什么时候 | 今日清单、日程与预览日历，区分待办和已安排块 |
| 插入紧急工作 | 不想手动重排全部任务 | 明确预览新增、移动、保留和未安排量 |
| 没按计划完成 | 希望调整而不是丢失历史 | 补记完成、自评、重排剩余工作，保留过去记录 |
| 需要陪伴或整理表达 | 希望获得建议、日记或分享文案 | AI 提案与草稿，用户核对后采用 |
| 更换手机 | 希望数据可恢复且私人内容不外泄 | 本地备份先行，账户分区与VIP主动备份／覆盖／兼容同步 |

## 3. 范围与优先级

P0：首个可演示闭环；P1：主要产品增强；P2：在基线稳定后评估。

### F01 快速记录与整理（P0）

- 标题必填，截止、预计工作量、重要度、标签和备注可后补；未补全的事项保留在收集箱，不能猜测工时自动排程。
- 提供完成、撤销完成、编辑、归档、搜索和标签过滤；删除有确认或可撤销路径。
- 工时支持分钟／小时／天，明确一天表示24小时预算，不等于每天都可连续工作24小时。
- 使用现有单事项模型，按事项维护截止和工时；本轮范围不含长期目标或阶段实体。
- 验收：最短路径创建、空标题拒绝、编辑／完成后重启保留、搜索能到达全部记录；重复点击不重复创建。

### F02 直观 Todo 分布（P0／P1）

- P0：今日清单、日计划时间线、未排事项和完成状态。
- 保留现有预览日历及活动月历，使用同一事项／安排数据源；取消独立日／周／月／学期切换和多尺度负荷图。
- 标题优先可读，短时间块有最小展示高度；展示空间变化不能修改实际起止。重叠事件分栏，完整信息可在详情查看。
- 颜色、文字、图标共同区分任务、忙碌、固定、完成与逾期，不能只靠颜色判断。
- 验收：清单、日程与预览日历统计一致，跨午夜正确拆分；大字体、暗色和窄屏仍能操作。

### F03 自动协调安排（P0）

- 输入截止、最早开始、预计工时、重要度、拆分策略；空闲支持每周和特定日期，忙碌支持一次和重复。
- 学习或工作事项可设置自身执行窗口；相邻、重叠区间按并集合并，真实空隙保留。
- 排程遵守可用时间、忙碌和事项截止，不把已完成预算再排一次；保留固定、过去与进行中安排。
- 临时插入后预览变化，确认应用；不能安排时显示未排分钟与可采取的调整，不越过截止凑满。
- 自动安排是可解释的启发式方案，不承诺数学上的全局最优。
- 验收：无重叠、工时守恒、截止和保护约束、连续任务不可跨空隙、重复输入幂等、跨尺度一致。

### F04 提醒（P0／P1）

- 本地通知与提前量为基础；精确提醒按系统能力和用户授权设计，不能把后台定时工作当精确闹钟。
- 任务改期、完成、撤销、删除后同步更新或取消提醒，重启和时区变化后重新核对。
- 权限拒绝、电池限制、勿扰等限制按需解释，并提供对应系统设置入口；不反复骚扰授权。
- 标准API36模拟器为共同基线；Bottledkzk已在小米14 Pro Android16实测，Weiding本人设备与结果待其补录。
- 验收：前台、后台、锁屏、重启、拒绝权限、重复提醒、改期取消各自记录，不用单次通知成功替代全部场景。

### F05 打卡与复盘（P0／P1）

- 完成可以记录实际时间、五档自评和可选反思；允许补记与更正，计划工时和实际完成分开统计。
- P0：每日完成条目与记录；P1：连续天数、事项进度、周期报告和本地日记。
- AI根据真实打卡生成日记／复盘草稿；日记有文学、严谨、精简、详细四风格，不输出注释汇报、不补造感受次数和时间，用户编辑后确认保存或丢弃。
- 验收：更正后统计重算、跨日和时区口径明确、不重复累计，删除任务不静默毁掉完成历史。

### F06 AI 对话 Agent 与辅助（P1，登录后使用）

- 必须先登录WhaleToDo账户；客户端仅访问自有服务器。用户不导入模型API Key，不填写供应商地址，不直连商业模型。服务端保管凭据、实际模型ID和路由，客户端只展示服务端允许使用的模型选项。
- 免费用户可签到获取积分，也可使用MOCK积分档位。服务端校验余额、预占并按累计真实token结算；VIP解锁日程编辑与主动日程同步，仍受服务端用量限额约束。
- 会话新建、历史、搜索、继续、归档／删除，输入与账户隔离；功能从同一对话入口选择。
- 辅助模式：拆解目标、生成待办、安排咨询、受控重排、周期复盘、日记、打卡短句及分享文字。
- 服务端校验登录、归属、权限、余额和限额后原子预占积分，再调用模型；用请求ID实现幂等，成功结算、失败释放，超时／断流可查询状态，不能靠重复点击重复扣分或绕过扣分。
- 修改操作采用“结构化提案—服务端与本地双重校验—用户预览确认—事务提交”。模型输出不能直接更改账户、积分、VIP、订单或权限，不能绕过固定、完成、截止和数据归属规则。
- 摘要共享可关闭；明确本次发送范围，默认不发送私人备注、照片、完整数据库或账户令牌。Agent 会话历史仅在本机按账户隔离，不参与云备份或账号资料同步；单次调用的服务端幂等／恢复回执另见账户方案。
- 空正文、截断、格式错误、超时、登录失效与积分不足分别处理；内部格式纠正不重复扣用户积分，供应商费用仍由服务端计量与熔断，不无限重试。
- 验收：匿名请求返回未登录；客户端无供应商凭据；重复签到／并发消费不超发、不透支；失败不部分落库；真实模型与模拟响应分别标记。详细流程见《账户-AI积分与安全方案》。

### F07 社交分享（P1）

- 固定几个可选版式生成今日安排／打卡图片；支持系统相册选图、调用系统相机拍照作为背景、裁剪预览和保存图片。模板具体数量后续确认，先保持少而清晰。
- 使用系统图片选择器并兼容回退方案；相机、URI授权、低内存、取消和保存失败分别处理，不要求无关的相册全盘访问权限。
- 支持文字、图片与AI配文；AI配文同样必须登录并使用服务端积分额度，由Bottledkzk提供统一AI能力，Weiding接入分享流程。生成文案可编辑，不自动发布。
- 目标包括QQ、微信好友、空间／动态、朋友圈、微博等。优先系统分享与保存图片；目标入口是否出现取决于安装客户端与平台能力。需要官方SDK、应用审核或AppID的专项入口另行联调，不能声称系统分享一定直达朋友圈。
- 默认隐藏备注、地点、账户等私人字段，分享前明确选择内容。分享调用成功或调起目标应用不等于最终发布成功，以可获得的回执和人工观察分别记录。
- 首轮不做社交关系链、站内即时聊天或自动发布。验收覆盖模板、选图／拍照、权限拒绝、用户取消、无目标软件、保存失败、隐私过滤及双方真机。

### F08 账户、同步与下载网站（P1，依赖服务环境）

- 支持本地访客记录。AI、签到积分、VIP、订单和云同步必须登录；基础离线能力不强制登录。
- 公开版使用邮箱验证码注册和密码登录，支持60秒重发等待、错误验证码、邮箱验证重置、退出、会话轮换／撤销与账户隔离；真实邮件已验收，未承诺短信找回。
- 身份认证、登录注册API、令牌刷新与客户端网络桥接由Weiding主责；数据库模式、迁移、备份与部署管理由Bottledkzk主责，身份表与权限规则双方共同评审。
- 登录不自动上传、覆盖或合并日程，只切换到当前账号的本地分区；访客记录保留在访客分区，不隐式导入账户。
- 设置增加“账户同步”：VIP 主动选择“云端备份”上传日程；主动选择“覆盖同步”或“兼容同步”读取云端备份，预览确认后才提交。兼容以本地同编号对象为准，冲突云端安排保留为待安排事项，不自动再次上传合并结果。
- 日记、昵称和 motto 自动随账号同步，离线修改保留并重试；两端同字段冲突需选择保留方式。Agent 会话、设备时区、外观与本地图片 URI 不跟随账号上传。
- 服务端裁决归属与 VIP，云端备份按版本比较更新；退出或切号后的旧响应不能写入新账号，失败保留本地数据。
- 网站提供真实版本、APK下载、SHA256、安装说明、变更记录和项目入口。官网与账户／AI服务已经部署，静态下载页不承担认证服务。
- 验收：错误密码、失效令牌、撤销会话、跨账户请求与离线恢复均有测试；域名、服务端、同步和真机状态分别记录。

### F09 UI、便捷操作与设备适配（跨阶段）

五个主要目的地为今天、待办、预览、助手、我的；快速新增可从常用页面触达。高频操作保持短路径，低频设置集中管理。统一鲸鱼品牌、留白密度、字号、状态和错误反馈；亮／暗／系统主题，壁纸和伙伴作为可关闭的个性化增强，不盖住关键操作。

适配目标：Android API26起，编译／目标SDK36的首轮基线；720—1440宽手机、大字体、手势导航、安全区、深色、横屏／大屏按矩阵验证。系统版本与设备实际结果以环境记录为准，不能按型号推断用户当前系统。

### F10 签到、VIP与简化支付（P1）

- 签到账本、积分预占／消费／释放／调整流水、VIP权益和订单由服务器决定；客户端只展示，不接受客户端直接设置余额或VIP状态。
- 每用户每业务日只能领取一次签到奖励，唯一约束与事务防并发重复；额度、套餐、价格、有效期及功能权限均为待定配置，不把占位数字当产品承诺。
- 课程演示先实现模拟支付通道：选择测试套餐→服务端建单→明显标注的模拟支付→服务端验证测试事件→更新订单与VIP权益。无真实资金、无银行卡信息，模拟入口仅开发／演示环境启用。
- 真实支付后续替换为合规的官方通道；服务器验签／查单、校验订单金额和币种后幂等发放权益。客户端“支付成功”页面或跳转参数不能作为入账依据。
- 验收：并发签到、重复请求、余额不足、失败释放、伪造／重复／乱序支付事件、订单越权和VIP过期。设计详见《账户-AI积分与安全方案》。

## 4. 关键数据与边界

| 对象 | 职责 |
| --- | --- |
| Task | 单事项与预算、截止、最早开始、重要度、归档 |
| Availability／BusyEvent | 可用时间与固定占用，自定义窗口和重复规则 |
| PlanBlock | 实际安排区间、固定、完成关联与修订号 |
| CheckIn | 实际完成、自评和反思，与计划量分开 |
| Conversation／Proposal | 对话上下文、可确认操作、版本与执行回执 |
| User／AuthSession／SyncState | 最少资料、认证会话、归属和同步版本，不含明文密码 |
| DailyClaim／PointWallet／PointLedger | 签到唯一性、余额、预占与可追踪流水 |
| AiRequest／ModelRoute | 幂等调用状态、用量和服务端模型路由，凭据单独受控保存 |
| Product／Order／PaymentEvent／Entitlement | 服务端套餐、订单、支付事件与VIP有效权益 |
| ShareDraft | 明确选择的分享内容、图片和隐私选项 |

所有时间按明确时区转换，持久层保留稳定ID与版本。导入、恢复和AI提案先校验，事务失败保留原数据；备份不含凭据。任何自动推断都需可见、可修改，不能把猜测当成用户确定信息。

## 5. 阶段范围与非目标

当前已完成本地纵向流程与账户／真实模型／MOCK订单／手动同步集成。公开0.5.3签名包完成基础真机流程，0.5.4完成日记增量补测；全部设备与通知场景按矩阵分别记录，不由单机演示覆盖。

课程范围不做独立日／周／月／学期视图、长期／多阶段模型、复杂社区、自动社交发布、现金提现、积分转账、复杂订阅续费、任意代码执行Agent或用户自带模型密钥。保留当前预览日历型视图。真实收款和上线部署按明确任务安排。具体分工以《分工与协作方案》为准；功能设计不等于已完成实现。
