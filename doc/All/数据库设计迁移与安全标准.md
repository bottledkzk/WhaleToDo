# 数据库设计、迁移与安全标准

版本1.1，2026-10-31。数据库Bottledkzk，认证／基础同步Weiding；当前主动账户文档与MOCK支付Bottledkzk承接。十条迁移与交付见[发行回执](../Bottledkzk/2026-10-31-0.5.4交付与验收.md)。

本文与同批代码由另一成员交叉评审后作为团队基线。SQL 注入、AI 提示词注入、Shell 注入是不同风险；此处重点规定数据库 SQL 注入防护，不承诺消除所有攻击。

## 1. 环境与数据设计

固定 PostgreSQL 16、Prisma 6.19.3、Node 24。现阶段最多十个账户、小连接池；“十个用户”不等于十个数据库直连。5432、8080、8081仅回环，公网经HTTPS反代；不改变主机其他443服务。

| 数据域 | 表 | 约束与权威来源 |
| --- | --- | --- |
| 账户/认证 | users、auth_sessions | 用户UUID稳定；username用于登录，display_name仅昵称；密码scrypt/Argon2id摘要，令牌仅摘要；role/status不接受客户端写入 |
| 内容 | tasks、plan_blocks、checkins、availability、user_settings | user_id归属、UUID、版本、时间区间和跨表复合外键；RLS与事务内认证身份 |
| 同步 | sync_batches、sync_mutations、sync_changes | 版本、批次/变更ID、回执和删除标记；基础同步Weiding；当前账号文档同步Bottledkzk承接，不能把日志追加当作内容表已更新 |
| 积分/AI | daily_claims、point_wallets、point_ledger、entitlements、ai_requests | 同一钱包/流水；签到唯一；消费预占/结算/释放原子；unknown不自动返还/重试 |
| 商品/订单 | products、orders、payment_events | 新增；金额整数分、显式environment、不可变快照、事件去重、订单归属、审计保留 |
| 邮件认证 | email_verifications、email_verify_tickets、email_throttle | 新增；仅HMAC/短期票据与共享计数，无验证码明文、原始IP或SMTP秘密 |
| 幂等 | idempotency_receipts | 服务端作用域与HMAC指纹；同键异体冲突；过期索引、受控清理 |

完整表清单以十条前向迁移为准；account_documents存独立schedule/profile文档、revision及归属。邮箱、MOCK订单和文档同步接口已部署，表存在仍不能替代业务验收。昵称接口权威为users.display_name，不另建第二套余额。历史保留的goals/stages不等于当前启用了长期多阶段产品模型。

时间点使用timestamptz(3)，绝对时间按UTC传输；业务日期由服务器BUSINESS_TIMEZONE计算，不由客户端时区决定。可重复当地时间/WorkingTime另存地区名、星期或日期及分钟；夏令时无效时刻必须拒绝或经用户选择，不静默改历史。

## 2. SQL 注入与权限硬性规则

1. Prisma CRUD或直接`$queryRaw`/`$executeRaw`标签模板；插值仅作参数。禁止Unsafe方法和Prisma.raw构建。pg只允许内联固定SQL与独立`$1`参数数组；禁止把请求拼入SQL、表名、排序或运算符。
2. 有限排序/对象名用服务内部白名单映射到固定SQL分支；不要把用户提供的字符串交给动态SQL。管理SQL若确需动态标识符，使用固定清单与PostgreSQL format `%I`，值用`USING`。
3. 不以替换单引号/过滤SELECT/黑名单作为防线；正常备注可以包含引号、分号、中文。类型、枚举、长度、UTF-8/JSONB实际大小校验解决边界与资源问题，不能代替参数化。
4. user_id/scope/VIP/积分由可信认证与业务事务决定；RLS用同一连接的事务内`set_config('app.user_id', value, true)`。连接复用不能留下会话级身份。RLS只隔离内容/订单，不代替内部认证表的API权限。
5. `whaletodo_app`无DDL/授予权限/改role能力；`whaletodo_ai`仅认证摘要、钱包、账本、请求及权益所需列；AI不能读内容、密码、订单或邮件表。迁移角色不能superuser/createdb/createrole/bypassrls，常驻服务不能使用迁移凭据。
6. 模型不能生成并执行SQL、调用管理命令或设置数据库身份。用户提案必须走既有结构化校验/授权；提示词不是数据库权限机制。
7. 对外统一受控错误码；日志不记录URL、密码、令牌、验证码、完整SQL参数、邮件正文和原始数据库异常。只保留request_id/状态/耗时/内部事件码。

`npm run db:security`按TypeScript AST检查运行源码中常见危险语法，纳入CI；它是审查门禁，不是完整污点分析或安全认证。参数化回归、数据库最小权限和人工评审必须同时保留。新引入查询封装/别名/动态执行需更新门禁并重新评审，不能绕过检查器。

## 3. 订单与邮箱落库契约

- orders不默认production，创建时显式写mock/production；首版业务仅启用mock，不创建真实收款服务/商品。正式通道后续须分环境/分权限，不用单一字段代替隔离。
- 商品修改不能改已生成订单。快照必须包含title/price_minor/currency/points/vip_days，金额/币种一致；身份、金额、环境、快照、创建时刻不可更新。
- 允许PENDING→PAID/CLOSED、PAID→REFUNDED；成功和退款需paid_at。payment_events唯一(provider,event_id)，额外要求currency；只存摘要。金额、验签、事件去重、状态转换、钱包账本与VIP发放须由支付模块在同一业务事务实现，当前MOCK链路Bottledkzk承接。
- 新orders对用户/商品使用RESTRICT，payment_events对订单RESTRICT；有订单不得物理删账户。entitlements的(user_id,source_order_id)复合外键防跨账户关联。既有账本删除语义未整体重构，不能声称全部审计对象永久保留。
- 首版mock回调必须显式提供currency；缺失或与订单快照不一致均400，不默认回落到订单币种，不变更PENDING或发放权益。未来真实通道的币种只能来自验签后的可信回执/官方查单，另行评审。
- 邮件限流按适用场景建立行：匿名注册和匿名找回密码至少email/IP/global三维；有认证身份的绑定操作再加account维度，已认证重置也可叠加本人account维度。找回密码不要求先登录，不因查询邮箱是否存在而泄露账户状态；不适用account时跳过，不能造空串/假ID或接受客户端指定账户。非global维度键均HMAC，global固定all。
- 邮箱验证码三表沿用队友命名。purpose仅register/reset/bind，无unbind。一个邮箱同用途只允许一条未消费码（过期未消费也占位，发新码前同事务作废旧码）。限流scope含email/ip/account/global；非global的scope_key全部HMAC，global固定all；count用integer，避免smallint在攻击流量下很快溢出。
- 邮件内部表不给AI或客户端直连；app仅SELECT/INSERT/UPDATE，无DELETE。绑定、重置、签发和消费必须核对purpose/email/有效期并原子消费；验证码5分钟/五次失败、票据60秒、60秒/小时/全局限流由Weiding的业务负责，不把数据库字段当作这些规则已经实现。

## 4. 迁移发布规则

已应用的migration.sql不可改名/改内容/删除。新需求新增前向迁移；DDL默认显式事务、短lock_timeout/statement_timeout，大表另评估锁与索引策略。禁止正式库migrate reset/db push/测试TRUNCATE；禁止直接在正式表调试。

`npm run db:history`对照PR基线/主分支阻断既有SQL的编辑或删除；可编辑的本地清单不能替代这个独立门禁。`checksums.json`保存每条SQL的LF和CRLF校验值：历史生产包实际使用CRLF，Git Linux检出为LF，仅接受这两种等价换行；内容变化仍阻断。新增`.sql eol=lf`统一后续文件，不回写历史数据库记录。

发布顺序：源版本冻结→离线测试→独立数据库从零迁移→最新正式备份→临时恢复库升级→行级数据不变/角色测试→另一成员评审→维护窗口部署→运行角色授权→健康与错误检查→私有发布凭据。

`db:plan <database>`核对目标、角色、历史校验、失败记录、只追加与待应用列表。`db:apply <database> <backup>`还要求同库30分钟内备份和校验匹配；只调用锁定版本Prisma migrate deploy，不输出原始CLI连接信息。完整空库CI可直接db:deploy；生产只用受控入口。门禁不代替真实结构漂移检查；手工DDL需人工比对/解释后补前向修复。

迁移失败时不自动修改_prisma_migrations、不自动resolve、不自动down。停止发布，保留备份/日志，检查失败状态；优先追加修复或恢复到新库核验后切换。不能在运行数据库直接覆盖恢复，也不强杀其他会话。

## 5. 备份、恢复与管理

- 每日03:15 UTC自定义格式全库备份，目录0700、文件0600；先.partial，成功后原子发布dump+SHA256+JSON元数据。互斥锁、100MiB余量、非空与归档目录检查；失败不发布完成标记。
- dump包含敏感的用户数据/密码摘要/会话摘要，但不包含角色密码、systemd凭据或外部配置。不能放仓库、网站、PR或未加密社交传输；数据库角色/秘密另行安全保管。
- 每周日04:00 UTC实际恢复到全新临时库，单事务/失败退出，核验迁移、约束、容量与钱包，再仅删除该次新建临时库。默认只选database=whaletodo的正式备份；不得混入测试库备份。
- 当次恢复凭据与备份SHA绑定。SHA256用于完整性核对，不能单独证明真实性；恢复只信任管理员控制来源，未知SQL归档不可执行。
- 同机备份不能抵御整机丢失。每次重要发布下载一份经过认证加密的离机副本，恢复密钥另存，不进Git。尚未配置自动离机同步时必须明确记录，不能称已实现自动异地容灾。
- 课程期保留全部成功备份，结束后至少30天；此小规模备份暂不自动删除，人工清理前确认离机副本和近期恢复通过。磁盘不足会阻断备份并留下systemd失败状态。
- RPO目标24小时、RTO目标30分钟，只是目标；以实际演练耗时为证据。配置timer≠已观察未来自动成功；失败从systemctl/journal检查，尚无已接通的邮件/短信报警。
- 当前生产仅启用备份/恢复，不启用定时清理。保留按小时运行的清理模板，单独启用后清理过期回执（过期7天后）、邮件码/票据（过期24小时后）、限流窗口（48小时后），每表每次最多1000行，短锁与SKIP LOCKED。保留账本、订单、unknown AI、会话重放链和同步墓碑，另行设计归档。

## 6. 必须提交的验证证据

SQL策略/类型/离线测试；独立PG16空库建表和旧版升级；跨账户与缺省身份RLS；运行角色拒绝DDL/越权；SQL攻击字符串按数据处理；重复订单事件和票据并发；真实备份恢复/坏校验拒绝；生产数据/服务前后状态。

公开PR只发合成测试摘要及可共享配置；私有证据记录精确版本、校验、时间、服务状态。区分已写代码、已合并、已验证、已生产部署与真实外部服务联调。

参考：[OWASP SQL注入防护](https://cheatsheetseries.owasp.org/cheatsheets/SQL_Injection_Prevention_Cheat_Sheet.html)、[PostgreSQL16 pg_dump](https://www.postgresql.org/docs/16/app-pgdump.html)、[PostgreSQL16 pg_restore](https://www.postgresql.org/docs/16/app-pgrestore.html)。Prisma命令以仓库锁定6.19.3的CLI为准。
