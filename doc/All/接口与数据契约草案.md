# 接口与数据契约草案

版本：0.3　状态：账户和 AI 已有生产基线；2026-10-30 新增主动云备份／资料同步契约，新版本是否部署以发布回执为准。

## 1. 统一约定

前缀 `/api/v1`，私有接口携带服务器访问令牌。用户身份由服务端认证取得，不信任请求体user_id。响应带request_id、data或明确error_code；时间为带偏移的ISO8601／UTC时间戳，业务日单独固定时区。分页、条数、文本与图片大小有上限。

写操作带Idempotency-Key；AI、签到、订单和同步批次必须幂等。相同键不同请求体拒绝，不复用其他用户结果。客户端超时可查询原请求状态，不能一律创建新请求。重试仅对可安全重试的请求使用，刷新令牌不触发业务重复执行。

## 2. 接口与负责人

| 契约 | 主责 | 主要行为 |
| --- | --- | --- |
| POST /auth/register、/auth/login、/auth/refresh、/auth/logout | Weiding | 密码校验、会话签发／轮换／撤销；注册不开放客户端选择role或VIP |
| GET /me、GET /me/entitlements | Weiding | 最少资料、有效权益；服务端裁决权限 |
| GET /rewards/daily、POST /rewards/daily/claim | Weiding | 签到状态与一次性奖励，事务使用统一账本 |
| GET /wallet、GET /wallet/ledger | Weiding | 只查本人余额／预占与分页流水 |
| GET /ai/models、POST /ai/requests、GET /ai/requests/{id} | Bottledkzk | 可用模型目录、受鉴权的统一模式请求、结果与用量状态 |
| GET /products、POST /orders、GET /orders/{id} | Weiding | 套餐快照、建单／查询本人订单；金额不由客户端决定 |
| POST /payments/{provider}/webhook | Weiding | 服务端验证的支付事件；不以客户端令牌代替网关验签 |
| POST /sync/push、GET /sync/pull?cursor=... | Weiding | 批次ID、对象版本、删除标记、分页游标与冲突 |
| /health/live、/health/ready | 双方 | 不返回密钥或内部拓扑；ready检查必要依赖 |
| GET／POST /account/cloud/schedule | Bottledkzk（本轮明确授权） | VIP 主动备份／读取，版本比较更新，不由登录触发 |
| GET／POST /account/cloud/profile | Bottledkzk（本轮明确授权） | 日记／昵称／motto 自动随账号；独立冲突与离线恢复 |

账户／订单／同步端主责Weiding；数据库模式和迁移主责Bottledkzk；AI积分消费主责Bottledkzk。签到奖励、订单发放与AI扣分共同调用同一账本事务，不各自改表绕过约束。

AI请求最少包含client_request_id、mode、conversation_id、允许的model_code和用户选中的context。mode涵盖chat、plan、review、diary、share_copy等；实际供应商模型ID仅服务器维护。mode枚举、Schema、流式事件与重连协议由双方冻结，不直接让客户端任意拼上游URL。

通用错误至少区分UNAUTHENTICATED、FORBIDDEN、VALIDATION_ERROR、INSUFFICIENT_POINTS、RATE_LIMITED、CONFLICT、UPSTREAM_UNAVAILABLE和REQUEST_PENDING。内部堆栈、SQL和供应商凭据不下发客户端。

## 3. 数据最小集

| 表／对象 | 必要字段／约束 | 主要维护 |
| --- | --- | --- |
| users、auth_sessions | 唯一用户名、password_hash；令牌摘要、到期与撤销 | Bottledkzk设计；Weiding实现身份业务 |
| tasks、goals、stages、availability、busy_events、plan_blocks、checkins | owner_user_id、稳定ID、版本、时间、删除标记；父约束与预算 | Bottledkzk；Weiding映射同步 |
| sync_cursors、mutation_receipts | 账户、设备逻辑ID、游标／批次与去重回执；不上传真实硬件标识 | 双方 |
| daily_claims、point_wallets、point_ledger | (user,business_date,reward_type)唯一；available／reserved非负；事件幂等 | 双方使用统一事务 |
| ai_requests | user、client_request_id唯一、状态、预占／结算、用量和提案版本 | Bottledkzk |
| products、orders、payment_events、entitlements | 服务端价格快照、金额最小货币单位、环境、事件唯一与有效期 | Weiding业务；Bottledkzk表与迁移 |
| conversation_metadata、proposal_receipts | 账户归属、可选历史索引、版本、确认回执；正文云存储策略后定 | Bottledkzk |

云端与本地字段不必逐列相同，但ID、版本、时区、删除与冲突映射必须明确。积分账本不随普通客户端同步写入，客户端只能从服务器读权威余额。

## 4. 同步冲突与离线

本地数据按访客／账户分区；登录时不自动上传全部访客记录。写入携带expected_version，服务端版本不符返回冲突和当前版本；普通文字字段可由用户选取，完成／删除／已锁定计划不可无提示覆盖。首轮先采用明确冲突提示，不做复杂CRDT。

服务端游标记录稳定变更序列，重复拉取可幂等应用；删除使用tombstone，不能因离线旧副本复活。退出、令牌失效或账户切换暂停同步并清空在途身份上下文。提醒由最终提交的领域事件触发，重复同步不能生成重复通知。

## 5. 交接及测试

Bottledkzk交付领域样例、数据约束／迁移、AI提案与用量格式；Weiding交付认证、错误、刷新、同步／订单接口与客户端封装。共享契约用PR相互确认后版本化。

模拟响应必须可辨认，不携带真实Key；不能把模拟登录、扣分或支付当线上验收。共同准备两账户越权、签到并发、幂等重试、版本冲突、离线重连、重复支付事件与AI余额不足用例。
