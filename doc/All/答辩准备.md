# 答辩准备

目标是讲清软件如何工作、为什么这样设计，以及证据如何支持结论。

## 演示主线

1. 快速添加事项并补充截止和工作量。
2. 配置空闲或忙碌，生成计划，解释未排量。
3. 插入紧急事项，对比保留与移动块。
4. 完成、自评、重启，展示真实持久化。
5. 按实际完成范围展示AI提案、分享和账户；未接通部分只讲设计，不伪造演示。

## 代码讲解点

- Compose状态→ViewModel→Repository→Room的数据流。
- core调度输入、区间并集／扣除、预算、排序、保护块和输出。
- 事务提案与失败回滚；模型输出为什么不能直接落库。
- 通知渠道、权限、后台限制和取消更新。
- 身份隔离、同步冲突、凭据与分享隐私。
- 一个真实遇到的问题、复现测试、修复和提交差异。

每位成员选定能讲清的核心代码和测试，不只背技术名词。代码引用用文件路径和提交SHA；演示包绑定版本和校验值。提交记录用于说明迭代与协作，不代替功能验收。

## 职责与新增讲解点

Bottledkzk重点讲前端状态、core排程、Room／服务器数据设计、AI受控提案与网站部署；Weiding重点讲认证网络、同步、提醒权限、相机／相册与分享、订单和支付适配。共同讲接口、事务、越权防护、费用上限和一次集成问题。

新增演示目标：登录→签到领积分→AI请求→一次扣分→提案确认；模拟支付必须清楚标识无真实资金，不能用客户端成功页代替服务器核验。未实现部分只讲方案，不伪造线上演示。
