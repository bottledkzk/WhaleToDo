# 答辩演示流程

更新2026-10-31，绑定0.5.4-preview.1。建议主演示约10分钟，注册／验证码与密码重置作为扩展支线，不在主线现场消耗过多等待时间。个人技术讲解见[Bottledkzk答辩说明](../Bottledkzk/2026-10-31-个人答辩技术说明.md)

## 演示前准备

确认官网／服务可用、手机网络稳定，准备合成日程与演示账号，余额和VIP足够且当日AI调用仍有余量。至少预留计划、编辑、日记、配文所需调用数；当天已耗尽额度的验收账号不直接用于下一场演示，不临场绕过限额。邮箱凭据和验证码只在本人设备使用，不进入投屏或答辩材料

演示日前将示例日期改为未来可用日期。以当地工作时间09:00–18:00、固定例会11:30–12:00、算法复习90分钟／12:00截止、彩排45分钟／17:00截止、材料整理30分钟和散步20分钟为例；要求工作60分钟后休息10分钟。不要照搬过期绝对日期

## 十分钟主线

| 时间 | 手机动作 | 讲解重点 |
| --- | --- | --- |
| 0:00–1:20 | 访客快速记下，补工时／截止，固定一项，自动安排并看待办／预览 | 本地优先，单事项与时间块分离；固定块保护 |
| 1:20–2:20 | 登录，展示头像／昵称／motto、7日签到和余额 | 访客不丢，账号分区；凭据与账本由服务器管理 |
| 2:20–3:10 | 选择充值档位，跳在线MOCK收银台，确认支付后回到账户 | 非真实资金，订单恢复、服务端幂等发权益 |
| 3:10–5:40 | 计划建议输入复杂约束，核对预览后人工Accept | 模型理解，确定性计算，约束和快照复核后事务写入 |
| 5:40–6:40 | 指定某事项移到下一天，检查原项和其他安排后Accept | 日期和对象绑定，时长不变，禁止修改固定／完成项 |
| 6:40–7:40 | 打卡一条合成事项，选日记风格，生成后编辑并保存 | 只用完成事实；四风格是表达选择，保存仍由人确认 |
| 7:40–8:40 | 生成分享配文，预览图片，保存或选择QQ发送 | 图片URI授权、草稿恢复、显式分享；展示后不必再次外发 |
| 8:40–10:00 | 设置内主动云备份，预览兼容／覆盖；退出回访客 | 资料自动跟随，日程主动同步，会话本地，访客记录保留 |

## 扩展和异常支线

注册与重置可额外用专用邮箱展示60秒倒计时、错误验证码和旧密码失效；不重复骚扰真实收件人。断网只需展示一次明确错误，再恢复网络。支付取消后回到同一待支付订单，避免现场重复建单。模型未返回时按原ID查询，不重复点击；资料同步可等待前台协调周期

网络或配额不满足时展示已验证的本地历史／合成预览，并明确这是历史结果，不伪称刚发生的新模型调用。Accept只能由演示者核对后操作。全程不展示邮箱密码、令牌、服务器私有路径或模型Key

## 两人讲解分工

Bottledkzk讲整体交互、core排程、Agent限制、Room／PostgreSQL、主动同步、MOCK支付与签名发布；Weiding讲认证与网络、验证码、提醒、媒体权限和ShareStudio。共同讲接口、事务、错误恢复和交叉评审；不把后续接手与原作者贡献混同

## 可以如实回答的限制

排程是启发式而非全局最优；日记守卫不是通用语义真值证明；全部支付为MOCK；QQ一次成功不等于所有平台成功；当前真机证据来自小米14 Pro，通知与多端长期运行仍需完整矩阵。头像本地图片URI不作为跨设备云头像上传
