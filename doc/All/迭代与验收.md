# 迭代与验收

迭代是相对顺序，不虚构课程截止日期。成员认领后再补工期、容量和排期。

| 里程碑 | 交付 | 完成条件 |
| --- | --- | --- |
| M0 基线 | 目标功能、架构、协作和环境脚本 | 仓库目录齐全；说明事实与规划；团队能讨论范围 |
| M1 本地纵向流程 | 可安装Android版本、快速事项、日计划、排程、打卡、持久化 | 规则检查通过；官方构建；模拟器创建与重启保持；安装包校验 |
| M2 主要增强 | 日／周／月、提醒、AI会话、事务提案、日记 | 核心约束回归；权限／错误路径；至少一家真实模型；真机待办场景 |
| M3 对外体验 | 分享图片／短句、下载页、账户与同步 | 真链接与隐私过滤；身份与跨账户测试；服务端部署条件满足 |
| M4 答辩候选 | 多设备回归、演示脚本、发布说明 | 每位成员可讲代码与测试；证据可复现；当前限制明确 |

提交按真实阶段形成：需求基线→工程环境→业务规则→持久化→界面闭环→站点／验证。不倒填日期，不用空提交虚增次数。阶段内的修复同样记录原因与验证。

## 验收层次

- 纯规则：确定性与生成场景、容量、预算、父约束、重叠、跨午夜和时区。
- 数据：创建／修改／归档、事务回滚、重启、升级和备份恢复。
- 构建：固定版本、依赖锁定、单元测试、APK输出与SHA256。
- 模拟器：真实控件操作、空状态、输入、状态反馈、重启和权限路径。
- 真机：小米14 Pro优先，通知、锁屏、后台、电池和分享单独验证。
- 外部：模型、账户服务、下载、社交目标应用单独联调，模拟响应不代表真实成功。

每份结果写明提交SHA、命令、环境、输入、预期、实际、证据路径和限制。记录失败，不反复覆盖成功数据；未测项标“未测”。
